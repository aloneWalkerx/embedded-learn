# 实验 9：OLED显示

本实验通过STM32F407ZGT6板载的PB3，PB5引脚以及1.3寸基于SH1106驱动芯片的外设OLED屏幕显示数字，字符，字母，中文（====底部有实验结果====）

### ① 时钟树

> **目标**：理解 OLED 显示相关的时钟来源与配置。

#### 与前面实验的时钟对比

| 实验             | 核心外设     | 主要时钟源              | 用途                 |
| -------------- | -------- | ------------------ | ------------------ |
| 实验 5（基本定时器）    | TIM6     | 内部 84MHz           | 产生固定周期中断           |
| 实验 6（PWM 输出）   | TIM3     | 内部 84MHz           | 生成 PWM 波形          |
| 实验 7（输入捕获）     | TIM5     | 内部 84MHz           | 测量信号脉宽             |
| 实验 8（脉冲计数）     | TIM2     | 外部脉冲信号             | 统计脉冲个数             |
| **实验 9（OLED）** | **GPIO** | **内部 84MHz（用于翻转）** | **模拟 I2C 时序驱动显示屏** |

> **核心区别**：OLED 显示没有使用片上外设（定时器、SPI等），而是完全依靠 **GPIO 软件模拟时序**，时钟仅用于 CPU 执行指令和产生微秒级延时。

### ② 寄存器级

> **目标**：从寄存器层面理解模拟 I2C 的工作原理。

#### 模拟 I2C 涉及的寄存器（GPIO 控制）

本实验 **没有使用硬件 I2C 外设**，直接操作 GPIO 的 **ODR**（输出数据寄存器）和 **MODER**（模式寄存器）。

| 寄存器              | 作用      | 本实验配置                                       |
| ---------------- | ------- | ------------------------------------------- |
| **GPIOB_MODER**  | 引脚模式寄存器 | 动态切换 PB5 为输出模式（发送数据）或输入模式（读取应答）             |
| **GPIOB_OTYPER** | 输出类型寄存器 | 推挽输出（PP）                                    |
| **GPIOB_PUPDR**  | 上下拉寄存器  | 输入时启用内部上拉（保证空闲电平高）                          |
| **GPIOB_ODR**    | 输出数据寄存器 | 置位/复位 SDA 和 SCL 引脚（由宏 `OLED_SDA_SET()` 等操作） |
| **GPIOB_IDR**    | 输入数据寄存器 | 读取 SDA 引脚电平（等待应答时用，尽管本实验未显式判断）              |

#### 关键时序的寄存器操作（以起始信号为例）

void IIC_Start(void)
{
    OLED_SDA_OUT();    // 设置 MODER 为输出模式
    OLED_SCL_SET();    // ODR 置位 SCL
    OLED_SDA_SET();    // ODR 置位 SDA
    delay_us(1);
    OLED_SDA_RESET();  // ★ ODR 复位 SDA → 起始信号（SCL=1 时 SDA 从 1→0）
    delay_us(1);
    OLED_SCL_RESET();  // ODR 复位 SCL
}

#### 从模式配置详解（纯软件模拟，无硬件从模式）

> **本实验无 TIM 外设，以下仅为对比说明**  
> 模拟 I2C 的“从模式”指主机遵循 I2C 协议，**主动**产生时序，不依赖硬件自动逻辑。

| 配置项       | 实现方式                           | 含义                           |
| --------- | ------------------------------ | ---------------------------- |
| **起始/停止** | 通过代码顺序拉高/拉低电平                  | 产生协议规定的跳变沿                   |
| **位发送**   | 循环移位判断，逐位设置 SDA，并翻转 SCL        | 每个 bit 严格遵循建立/保持时间           |
| **应答检测**  | 释放 SDA 后读取 IDR 电平（本实验简化）       | 可扩展为判断从机是否响应（本实验默认正常）        |
| **速度控制**  | `delay_us(1)` 决定每 bit 时长，约 1µs | 总速率 ≈ 500kHz（在 SH1106 允许范围内) |

### ③ 数据流

> **目标**：理清从“调用显示函数”到“像素点亮”的完整链路。

┌──────────────────────────────────────────────────────────────────────────────┐
│                    OLED 显示完整数据流（字符串 → 屏幕像素）                  │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  【应用层】（main.c 或 test.c）                                              │
│                                                                              │
│  OLED_ShowString(0, 0, "Hello", 16, 1)                                     │
│       │                                                                      │
│       ▼                                                                      │
│  【图形绘制层】（oled.c）                                                    │
│                                                                              │
│  ① OLED_ShowString 循环调用 OLED_ShowChar                                   │
│     │                                                                        │
│     ▼                                                                        │
│  ② OLED_ShowChar 从字库（F8X16[ ]）取出 16 字节点阵数据                      │
│     │   每个字节代表一行的 8 个像素点                                        │
│     │   逐位判断：1 则调用 OLED_SetPixel                                    │
│     ▼                                                                        │
│  ③ OLED_SetPixel 计算显存索引                                               │
│     index = (y / 8) * 128 + x                                               │
│     mask = 1 << (y % 8)                                                    │
│     修改 OLED_Buffer[index] 的对应位（置位/清零）                           │
│                                                                              │
│  ④ 所有字符处理完成后，调用 OLED_Display()                                  │
│     │                                                                        │
│     ▼                                                                        │
│  【驱动层】（iic.c 和 iic.h）                                                │
│                                                                              │
│  ⑤ OLED_Display 遍历 8 页（每页 8 行）                                      │
│     for page = 0 to 7:                                                      │
│        发送页地址命令（0xB0+page）                                          │
│        发送列地址命令（0x02, 0x10）                                         │
│        连续发送该页 128 个字节（从 OLED_Buffer 中取出）                     │
│                                                                              │
│  ⑥ 每个字节通过 Write_IIC_Data() 发送                                       │
│     │   ① IIC_Start()                                                       │
│     │   ② Write_IIC_Byte(0x78)  // 从机地址                                │
│     │   ③ IIC_Wait_Ack()                                                    │
│     │   ④ Write_IIC_Byte(0x40)  // 数据控制字节                            │
│     │   ⑤ IIC_Wait_Ack()                                                    │
│     │   ⑥ Write_IIC_Byte(byte)  // 真正数据                                │
│     │   ⑦ IIC_Wait_Ack()                                                    │
│     │   ⑧ IIC_Stop()                                                        │
│     │                                                                        │
│     └── 最终通过 PB3（SCL）和 PB5（SDA）引脚输出到 OLED                    │
│                                                                              │
│  【硬件层】（物理引脚和 OLED 芯片）                                          │
│                                                                              │
│  ① SCL/SDA 电平变化（严格按照 I2C 时序）                                     │
│  ② SH1106 内部显存更新（对应地址的字节被写入）                               │
│  ③ 像素显示（SEG/COM 驱动电路点亮对应像素）                                 │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

#### 显存布局（关键）

- **大小**：128 × 64 位 = 1024 字节

- **组织方式**：8 页（Page），每页 8 行，每行 128 列

- **索引公式**：`buffer_index = page × 128 + column`

- **位映射**：字节的 bit0 对应页内第 0 行，bit7 对应第 7 行

### ④ 中断/DMA 机制

> **目标**：理解 OLED 驱动是否使用中断或 DMA。

#### 本实验的中断/DMA 方案：**无中断，无 DMA，纯轮询**

| 机制      | 是否使用 | 说明                                    |
| ------- | ---- | ------------------------------------- |
| **中断**  | 否    | 所有时序由软件延时控制，无外设中断（不使用硬件 I2C，无定时器中断）   |
| **DMA** | 否    | 未使用 DMA 传输，所有数据由 CPU 逐个字节发送，效率较低但简单可靠 |

#### 与输入捕获/脉冲计数实验的对比

| 维度           | 输入捕获（实验 7）  | 脉冲计数（实验 8） | OLED 显示（本实验）          |
| ------------ | ----------- | ---------- | --------------------- |
| **中断类型**     | 捕获中断 + 溢出中断 | 仅溢出中断      | **无中断**               |
| **CPU 介入频率** | 每个脉冲中断      | 仅溢出时中断     | **每次发送都需要 CPU**       |
| **CPU 占用率**  | 中           | 低          | **高（但显示量小可接受）**       |
| **主要耗时**     | 中断处理        | 计数硬件       | **发送 1024 字节（约 2ms）** |

> **为什么不用中断？**  
> 模拟 I2C 要求严格的建立/保持时间（微秒级），若使用中断，响应延迟会导致时序错乱，屏幕花屏。采用 **延时轮询** 是最稳定、最简单的方法，适合对实时性要求不高的显示任务。

> ### ⑤ 改参实验
> 
> > **目标**：通过修改参数验证对 OLED 驱动和显示的理解。
> 
> #### 改参实验 1：修改 I2C 通信速度
> 
> **操作**：将 `iic.c` 中所有 `delay_us(1)` 改为 `delay_us(5)` 或 `delay_us(10)`。
> 
> **现象**：屏幕刷新明显变慢，但通信更稳定（尤其是飞线较长时）。
> 
> **结论**：`delay_us` 决定 SCL 频率，数值越大速度越慢，但抗干扰能力增强。
> 
> ---
> 
> #### 改参实验 2：修改屏幕扫描方向（左右镜像）
> 
> **操作**：在 `OLED_Init()` 中将 `OLED_WR_Byte(0xA1, OLED_CMD);` 改为 `0xA0`。
> 
> **现象**：显示内容左右翻转（镜像）。
> 
> **结论**：`0xA1` 为段重映射开启（镜像），`0xA0` 为关闭，可适应不同硬件走线。
> 
> ---
> 
> #### 改参实验 3：修改屏幕扫描方向（上下镜像）
> 
> **操作**：在 `OLED_Init()` 中将 `OLED_WR_Byte(0xC8, OLED_CMD);` 改为 `0xC0`。
> 
> **现象**：显示内容上下颠倒。
> 
> **结论**：`0xC8` 为 COM 扫描方向从下到上（常规），`0xC0` 为从上到下。
> 
> ---
> 
> #### 改参实验 4：修改对比度（亮度）
> 
> **操作**：在 `OLED_Init()` 中将 `OLED_WR_Byte(0xFF, OLED_CMD);`（对比度值）改为 `0x7F` 或 `0x10`。
> 
> **现象**：屏幕亮度变低。
> 
> **结论**：对比度值范围 0x00~0xFF，值越大越亮（电流消耗也越大）。
> 
> ---
> 
> #### 改参实验 5：修改显存清空颜色
> 
> **操作**：将 `OLED_Clear(0);` 改为 `OLED_Clear(1);`（在 `main()` 或初始化中）。
> 
> **现象**：开机或清屏后显示全白，而非全黑。
> 
> **结论**：`OLED_Clear` 通过 `memset` 填充 `0x00`（黑）或 `0xFF`（白）实现清屏。
> 
> ---
> 
> #### 改参实验 6：修改列地址偏移（适配不同驱动）
> 
> **操作**：在 `oled.h` 中将 `#define XLevelL 0x02` 改为 `0x00`。
> 
> **现象**：画面整体左移 2 列，右侧出现黑边（适用于 SSD1306）。
> 
> **结论**：SH1106 列地址从 0x02 开始，SSD1306 从 0x00 开始，修改该宏可适配不同屏幕。
> 
> ---
> 
> #### 改参实验 7：手动触发全屏刷新频率
> 
> **操作**：在主循环中延时调用 `OLED_Display()`（例如每 500ms 调用一次）。
> 
> **现象**：屏幕内容以 2Hz 频率更新，可观察动画效果。
> 
> **结论**：刷新频率由软件控制，可灵活用于低功耗或动态显示场景。
