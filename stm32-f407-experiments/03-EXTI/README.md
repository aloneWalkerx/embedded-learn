#### 本实验涉及的 GPIO 时钟与中断映射

| 按键            | GPIO 引脚 | 所在端口  | 时钟使能寄存器位          | EXTI 中断线 | 中断服务函数               |
| ------------- | ------- | ----- | ----------------- | -------- | -------------------- |
| **WKUP（板载）**  | PA0     | GPIOA | RCC->AHB1ENR bit0 | EXTI0    | EXTI0_IRQHandler     |
| **KEY0（板载）**  | PE4     | GPIOE | RCC->AHB1ENR bit4 | EXTI4    | EXTI4_IRQHandler     |
| **KEY_R（外设）** | PB10    | GPIOB | RCC->AHB1ENR bit1 | EXTI10   | EXTI15_10_IRQHandler |
| **KEY_Y（外设）** | PB11    | GPIOB | RCC->AHB1ENR bit1 | EXTI11   | EXTI15_10_IRQHandler |
| **KEY_G（外设）** | PB12    | GPIOB | RCC->AHB1ENR bit1 | EXTI12   | EXTI15_10_IRQHandler |

> **关键理解**：外部中断本身不需要单独的时钟，但 **GPIO 时钟必须开启**（否则引脚无法工作），同时 **SYSCFG 时钟也必须开启**，因为引脚到 EXTI 线的映射由 SYSCFG 模块控制。SYSCFG 时钟挂载在 **APB2 总线**上

### ④ 中断/DMA 机制

> **目标**：理解外部中断（EXTI）的核心机制及与中断系统的关系。

#### 本实验的核心机制：外部中断（EXTI）

EXTI 是 STM32 中用于检测外部信号边沿变化并触发中断或事件的模块。

**EXTI 的 22 条中断线（STM32F4）**：

| 中断线范围           | 用途                      | 中断服务函数                                  |
| --------------- | ----------------------- | --------------------------------------- |
| EXTI0 ~ EXTI4   | 独立中断线（每条线独立 ISR）        | `EXTI0_IRQHandler` ~ `EXTI4_IRQHandler` |
| EXTI5 ~ EXTI9   | **共享中断线**（5 条线共用一个 ISR） | `EXTI9_5_IRQHandler`                    |
| EXTI10 ~ EXTI15 | **共享中断线**（6 条线共用一个 ISR） | `EXTI15_10_IRQHandler`                  |
| EXTI16 ~ EXTI21 | 内部事件（PVD、RTC、USB 等）     | 各自独立                                    |

#### 中断 vs 轮询 对比

| 特性           | 轮询（Polling）    | 外部中断（EXTI）          |
| ------------ | -------------- | ------------------- |
| **CPU 参与方式** | CPU 主动反复查询引脚状态 | 硬件在事件发生时主动通知 CPU    |
| **CPU 占用率**  | 高（大部分时间在空转查询）  | 极低（无事时可休眠或执行其他任务）   |
| **实时性**      | 响应延迟取决于查询周期    | **事件发生立即响应**（微秒级）   |
| **代码复杂度**    | 简单（循环 + if 判断） | 中等（需配置 NVIC、编写 ISR） |
| **适用场景**     | 按键检测、低频信号      | 紧急事件、高频信号、低功耗系统     |

#### 中断模式 vs 事件模式

EXTI 可以工作在两种模式下：

| 模式                  | 说明                         | 本实验      |
| ------------------- | -------------------------- | -------- |
| **中断模式（Interrupt）** | 产生中断请求 → CPU 响应 → 执行 ISR   | ✅ **使用** |
| **事件模式（Event）**     | 产生脉冲信号 → 触发其他硬件（如 DMA、定时器） | ❌ 未使用    |

#### NVIC 中断优先级管理

本实验中的优先级配置：

c

// 抢占优先级 = 0，子优先级 = 0
// 所有外部中断平级，不会互相打断
HAL_NVIC_SetPriority(EXTI0_IRQn, 0, 0);
HAL_NVIC_SetPriority(EXTI4_IRQn, 0, 0);
HAL_NVIC_SetPriority(EXTI15_10_IRQn, 0, 0);

**NVIC 优先级分组（在 `HAL_Init()` 中默认设置为 Group 4）**：

| 分组模式        | 抢占优先级位数 | 子优先级位数 | 抢占优先级取值范围 | 子优先级取值范围 |
| ----------- | ------- | ------ | --------- | -------- |
| **GROUP_0** | 0 位     | 4 位    | 仅 0       | 0-15     |
| **GROUP_1** | 1 位     | 3 位    | 0-1       | 0-7      |
| **GROUP_2** | 2 位     | 2 位    | 0-3       | 0-3      |
| **GROUP_3** | 3 位     | 1 位    | 0-7       | 0-1      |
| **GROUP_4** | 4 位     | 0 位    | 0-15      | 仅 0      |

#### 中断服务函数（ISR）的命名规则

**ISR 函数名必须与启动文件（`startup_stm32f407xx.s`）中的向量表定义完全一致！**

assembly

; startup_stm32f407xx.s 中的中断向量表
__Vectors
 DCD EXTI0_IRQHandler ; ← 固定名称
 DCD EXTI1_IRQHandler ; ← 固定名称
 ...
 DCD EXTI9_5_IRQHandler ; ← 固定名称
 DCD EXTI15_10_IRQHandler ; ← 固定名称

**如果函数名写错**：编译器找不到匹配的函数 → 链接器使用启动文件中的 `[WEAK]` 默认函数（死循环） → 按键按下后程序卡死。

#### 共享中断线的处理

对于 `EXTI15_10_IRQHandler`，需要在 ISR 中**分别处理每一个可能产生中断的引脚**：

c

void EXTI15_10_IRQHandler(void)
{
 // 判断并处理 PB10 的中断
 if (__HAL_GPIO_EXTI_GET_IT(GPIO_PIN_10) != RESET) {
 HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_10);
 }
 // 判断并处理 PB11 的中断
 if (__HAL_GPIO_EXTI_GET_IT(GPIO_PIN_11) != RESET) {
 HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_11);
 }
 // 判断并处理 PB12 的中断
 if (__HAL_GPIO_EXTI_GET_IT(GPIO_PIN_12) != RESET) {
 HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_12);
 }
}

#### 中断服务函数中的注意事项

> **⚠️ 黄金法则：中断服务函数（ISR）必须快进快出！**

| 允许的操作                       | 禁止的操作                          |
| --------------------------- | ------------------------------ |
| ✅ 读取寄存器/标志位                 | ❌ 阻塞延时（`delay_ms`、`HAL_Delay`） |
| ✅ 设置标志位（通知主循环）              | ❌ 大量数据处理                       |
| ✅ 清除中断标志位                   | ❌ 复杂数学运算                       |
| ✅ 简单变量操作                    | ❌ `printf` 或串口发送（耗时）           |
| ✅ 调用 HAL 库的 `IRQHandler` 函数 | ❌ 等待外部事件（如按键释放）                |

#### DMA 机制说明

**本实验未使用 DMA**。

DMA（Direct Memory Access，直接内存访问）是一种无需 CPU 参与即可在内存和外设之间传输数据的机制，通常用于 ADC 采样、串口接收、SPI 通信等需要大批量数据传输的场景。按键中断属于**事件驱动型**任务，数据量极小（只是一个电平变化信号），使用 DMA 反而会浪费资源

### ⑤ 改参实验

> **目标**：通过修改参数/配置，验证对外部中断的理解。

#### 改参实验 1：修改触发方式（上升沿 ↔ 下降沿）

**操作**：将 WKUP（PA0）的触发方式从 `GPIO_MODE_IT_RISING` 改为 `GPIO_MODE_IT_FALLING`。

c

gpio_init_struct.Mode = GPIO_MODE_IT_FALLING; // 改为下降沿触发

**现象**：按下按键时 LED 不翻转，**松开按键时** LED 翻转。

**结论**：触发方式决定了中断发生的时刻。上升沿检测的是“0→1”的跳变（按下），下降沿检测的是“1→0”的跳变（松开）。

#### 改参实验 2：修改上下拉配置

**操作**：将 WKUP 的 `GPIO_PULLDOWN` 改为 `GPIO_PULLUP`，同时触发方式保持 `GPIO_MODE_IT_RISING`。

**现象**：

- 未按下时：引脚被上拉电阻拉到高电平（3.3V），`HAL_GPIO_ReadPin` 读到 1。

- 按下时：按键将引脚拉低到 GND（0V），但由于配置的是上升沿触发，**没有检测到 0→1 的跳变**，中断不触发。

**结论**：上下拉配置决定了未按下时的默认电平。触发方式检测的是**电平跳变方向**，必须与按键电路的实际跳变方向匹配。

#### 改参实验 3：修改中断优先级（观察中断嵌套）

**操作**：将 WKUP 的抢占优先级设为 1，KEY0 的抢占优先级设为 0。

c

HAL_NVIC_SetPriority(WKUP_EXT_IRQn, 1, 0); // 优先级低（数字大）
HAL_NVIC_SetPriority(KEY0_EXT_IRQn, 0, 0); // 优先级高（数字小）

**现象**：如果 KEY0 中断正在执行（比如加了一个长延时），WKUP 中断触发时，**不会打断 KEY0 的执行**，因为 WKUP 的优先级更低。

**结论**：抢占优先级数字小的优先级高，高优先级可以打断低优先级。

#### 改参实验 4：共享中断线的多个引脚同时触发

**操作**：同时按下 PB10 和 PB11（外设按键 R 和 Y）。

**现象**：`EXTI15_10_IRQHandler` 中会依次调用两次 `HAL_GPIO_EXTI_IRQHandler`，先后执行两个按键对应的 LED 翻转。

**结论**：共享中断线的多个引脚可以独立触发，在 ISR 中依次判断即可。

#### 改参实验 5：忘记清除中断标志位

**操作**：注释掉 `HAL_GPIO_EXTI_IRQHandler` 或 `__HAL_GPIO_EXTI_CLEAR_IT` 调用。

**现象**：按下一次按键后，LED 翻转一次，然后程序**陷入无限循环**，反复进入同一个中断（因为硬件看到标志位未清除，认为中断仍挂起）。

**结论**：在中断服务函数中**必须清除中断标志位**，否则会导致中断死循环。

#### 改参实验 6：中断里使用阻塞延时

**操作**：在 `HAL_GPIO_EXTI_Callback` 中加入 `delay_ms(500)`。

c

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
 delay_ms(500); // 阻塞延时
 LED_TOGGLE();
}

**现象**：按下按键后，LED 要等 500ms 才翻转。如果在这 500ms 内按下其他按键，系统无响应（因为 CPU 被阻塞在延时里）。

**结论**：**中断中禁止使用阻塞延时！** 生产项目中应采用“标志位 + 主循环处理”的方式。

### 踩坑记录

> **目标**：记录调试过程中遇到的实际问题及解决方法。

| 序号  | 问题现象                           | 原因分析                                          | 解决方法                                                         |
| --- | ------------------------------ | --------------------------------------------- | ------------------------------------------------------------ |
| 1   | **编译报错 `EXT0_IRQn` undefined** | 拼写错误：`EXT0`（数字0）应为 `EXTI0`（字母 I）              | 统一使用 `EXTIx_IRQn`，注意字母 I 不是数字 1/0                            |
| 2   | **按键按下后程序卡死（无限进入中断）**          | 中断标志位未清除                                      | 调用 `HAL_GPIO_EXTI_IRQHandler` 或手动 `__HAL_GPIO_EXTI_CLEAR_IT` |
| 3   | **中断响应一次后不再响应**                | 中断标志位未清除                                      | 同上                                                           |
| 4   | **按下和松开都触发中断**                 | 同时配置了上升沿和下降沿触发（`GPIO_MODE_IT_RISING_FALLING`） | 只配置需要的触发方式                                                   |
| 5   | **同一个中断线多个引脚只有一个能工作**          | `SYSCFG_EXTICR` 寄存器只能映射一个引脚到一条中断线             | 不同引脚用不同中断线（如 PA0→EXTI0，PB1→EXTI1）                            |
| 6   | **共享中断线（10~15）只有第一个引脚生效**      | ISR 中只调用了 `HAL_GPIO_EXTI_IRQHandler` 一次       | 在 ISR 中为**每个引脚**分别调用 `HAL_GPIO_EXTI_IRQHandler`              |

#### ⚠️ 经典踩坑总结

> **最大的坑：在中断服务函数中使用阻塞延时（如 `delay_ms`）！**
> 
> 官方例程中为了演示方便，在 `HAL_GPIO_EXTI_Callback` 里放了 `delay_ms(20)` 做消抖，但**生产项目中绝对不能这样写**。中断里做延时会阻塞 CPU，导致其他中断无法响应、主循环停滞、系统实时性严重下降。
> 
> **正确做法**：中断里只做“设置标志位”和“清除中断标志”，业务逻辑（包括消抖、LED 翻转等）放到主循环中处理。

#### 🔑 核心理解纠正

> **`EXTI0_IRQn` 是中断号（索引），`EXTI0_IRQHandler` 是中断服务函数（入口地址）**
> 
> - `EXTI0_IRQn`：给 NVIC 硬件看的编号，用于配置使能和优先级。在 CMSIS 标准中属于 `IRQn_Type` 枚举类型。
> 
> - `EXTI0_IRQHandler`：CPU 执行的中断服务函数入口地址。函数名必须与启动文件中的向量表完全一致。
> 
> 两者关系：中断号是向量表的**索引**，中断服务函数名是向量表中填的**地址**。硬件响应中断时，通过中断号找到向量表位置，取出服务函数地址，跳转执行。
