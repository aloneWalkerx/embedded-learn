#### 本实验涉及的 GPIO 时钟

| 按键            | 引脚             | 所在总线 | 时钟使能寄存器        | 对应位           |
| ------------- | -------------- | ---- | -------------- | ------------- |
| **WK_UP**     | PA0            | AHB1 | `RCC->AHB1ENR` | bit0（GPIOAEN） |
| **KEY0**      | PE4            | AHB1 | `RCC->AHB1ENR` | bit4（GPIOEEN） |
| **KEY_R/Y/G** | PB10/PB11/PB12 | AHB1 | `RCC->AHB1ENR` | bit1（GPIOBEN） |

#### 代码实现（底层寄存器操作）

c

// HAL 库宏展开后的本质
__HAL_RCC_GPIOA_CLK_ENABLE();  // → RCC->AHB1ENR |= (1 << 0)
__HAL_RCC_GPIOE_CLK_ENABLE();  // → RCC->AHB1ENR |= (1 << 4)
__HAL_RCC_GPIOB_CLK_ENABLE();  // → RCC->AHB1ENR |= (1 << 1)

> **关键理解**：GPIO 挂载在 **AHB1 总线**上。使能时钟的本质是往 `RCC_AHB1ENR` 寄存器的对应位写 1。**同一端口的多个引脚，只需使能一次时钟**



### ② 寄存器级

> **目标**：从寄存器层面理解 GPIO 输入模式的配置与读取过程。

#### STM32F407 GPIO 相关寄存器（输入模式）

| 寄存器       | 作用                              | 本实验配置                    |
| --------- | ------------------------------- | ------------------------ |
| **MODER** | 模式控制（00输入 / 01输出 / 10复用 / 11模拟） | `00`（输入模式）               |
| **PUPDR** | 上下拉控制（00无 / 01上拉 / 10下拉 / 11保留） | 板载：`10`（下拉）/ 外设：`01`（上拉） |
| **IDR**   | 输入数据寄存器（只读，反映引脚当前电平）            | 程序读取此寄存器判断按键状态           |

#### GPIO 配置的寄存器级操作（以 WKUP_PA0 为例）

c

// 1. 使能 GPIOA 时钟
RCC->AHB1ENR |= (1 << 0);   // bit0 置 1
// 2. 配置 PA0 为输入模式（MODER 的 bit1:0 = 00）
GPIOA->MODER &= ~(3 << 0);  // 清除 bit1:0
// 3. 配置 PA0 为下拉输入（PUPDR 的 bit1:0 = 10）
GPIOA->PUPDR &= ~(3 << 0);  // 先清除 bit1:0
GPIOA->PUPDR |=  (2 << 0);  // 再写入 10（下拉）
// 4. 读取 PA0 电平（IDR 的 bit0）
uint8_t status = (GPIOA->IDR >> 0) & 0x01;  // 1=高电平, 0=低电平

#### 本实验两种硬件电路的寄存器配置对比

| 按键类型                | 硬件电路           | GPIO 配置         | PUPDR 值 | 未按下电平   | 按下电平    |
| ------------------- | -------------- | --------------- | ------- | ------- | ------- |
| **板载按键**（WKUP/KEY0） | 按下接 VCC（高电平有效） | `GPIO_PULLDOWN` | `10`    | 0V（低）   | 3.3V（高） |
| **外部按键**（R/Y/G）     | 按下接 GND（低电平有效） | `GPIO_PULLUP`   | `01`    | 3.3V（高） | 0V（低）   |

> **设计原则**：上下拉配置的目的，是在按键**未按下**时给引脚一个**确定的默认电平**，防止悬空干扰。

#### 数据流中的关键转换点

| 阶段        | 数据表示     | 示例（外部按键）                          | 说明                    |
| --------- | -------- | --------------------------------- | --------------------- |
| **物理层**   | 电压信号     | 3.3V → 0V                         | 按下瞬间电压变化              |
| **寄存器层**  | 位值       | IDR bit = 1 → 0                   | 硬件自动更新                |
| **HAL 层** | 枚举值      | `GPIO_PIN_SET` → `GPIO_PIN_RESET` | `HAL_GPIO_ReadPin` 返回 |
| **宏定义层**  | 物理电平 0/1 | `KEY_R_STATUS` = 1 → 0            | 仅读取，不定义语义             |
| **扫描函数层** | 语义判断     | 检测到 `0` → 识别为按下                   | **语义在此层定义**           |
| **应用层**   | 键值宏      | `KEY_R_PRESS`                     | 返回给主程序                |

#### 扫描函数状态机

c

// key_release = 1：按键已释放（可触发新按键）
// key_release = 0：按键已按下（阻止重复触发）
[已释放] --按下--> [消抖延时10ms] --确认按下--> [已按下，返回键值]
    ↑                                                    |
    |                                                    |
    └────────── 全部释放，恢复标志 ──────────────────────┘

> **关键理解**：`KEY_R_STATUS` 宏只负责**读取物理电平**（0或1），不代表“按下”或“释放”的语义。**语义由扫描函数中的判断条件 `== 0` 或 `== 1` 定义。** 这种分层设计使得代码更灵活——如果硬件变动，只需修改宏定义中的判断条件，扫描函数逻辑不受影响。

### ④ 中断/DMA 机制

> **目标**：说明本实验未使用中断，但分析可能的中断方案及扩展思路。

#### 本实验方案：轮询（Polling）

- **实现方式**：主循环中反复调用 `key_scan()` 检测按键。

- **优点**：逻辑简单，不涉及中断优先级配置，适合入门学习。

- **缺点**：占用 CPU 时间（含 `delay_ms(10)` 消抖阻塞），实时性较差，CPU 无法在按键等待期间处理其他任务。

#### 扩展方案对比

| 方案             | 实现方式        | 优点             | 缺点                |
| -------------- | ----------- | -------------- | ----------------- |
| **轮询（本实验）**    | 主循环持续调用扫描函数 | 简单直观，适合入门      | 占用 CPU，无法处理长按/组合键 |
| **外部中断（EXTI）** | GPIO 边沿触发中断 | CPU 空闲可休眠，功耗低  | 需处理中断优先级和重入问题     |
| **定时器扫描**      | 定时器中断中周期性扫描 | 消抖精度高，可识别长按/双击 | 实现复杂度较高           |



### ⑤ 改参实验

> **目标**：通过改变参数/配置，验证对 GPIO 输入和按键扫描的理解。

#### 改参实验 1：互换上下拉配置

**操作**：将板载按键的 `GPIO_PULLDOWN` 改为 `GPIO_PULLUP`。

**现象**：

- 未按下时，引脚被内部上拉电阻拉到 3.3V，`WKUP_STATUS` 读到 1

- 按下时，外部按键将引脚拉到 GND，`WKUP_STATUS` 读到 0

- 因扫描函数仍检测 `== 1` 表示按下，逻辑完全反转：**未按下反而检测到按键！**

**结论**：上下拉配置必须与 **硬件电路** 和 **扫描函数的判断逻辑** 三者配套，否则按键逻辑错误。

#### 改参实验 2：修改消抖延时

**操作**：将 `delay_ms(10)` 改为 `delay_ms(1)`。

**现象**：按下一次按键，可能触发 2~3 次，输出重复打印。

**原因**：消抖时间不足，机械抖动还未平息就进行第二次读取。

**操作**：将 `delay_ms(10)` 改为 `delay_ms(100)`。

**现象**：按键响应明显迟钝，按下后要等 100ms 才响应。

**结论**：消抖延时 **5~20ms** 是经验最佳值，过长影响响应速度，过短消抖不彻底。

#### 改参实验 3：切换单次/连续触发模式

**操作**：将 `key_scan(0)` 改为 `key_scan(1)`。

**现象**：

- `mode = 0`（单次）：按键按下只触发一次，必须释放再按才响应。

- `mode = 1`（连续）：按住按键不放，持续触发（约每 10ms 一次）。

**原理**：`mode = 1` 时，每次调用扫描函数开头强制 `key_release = 1`，相当于“忘记”上次已按下的状态，从而实现按住连发。

**应用场景**：单次触发适用于菜单选择/开关切换；连续触发适用于音量调节/数值增减。

#### 改参实验 4：同一端口多个引脚合并初始化

**操作**：将三个外部按键（PB10/PB11/PB12）的初始化合并为一次 `HAL_GPIO_Init` 调用：

c

gpio_init_struct.Pin = KEY_R_GPIO_PIN | KEY_Y_GPIO_PIN | KEY_G_GPIO_PIN;
HAL_GPIO_Init(KEY_R_GPIO_PORT, &gpio_init_struct);

**现象**：三个按键功能正常，与分开初始化无任何区别。

**结论**：**同一端口、相同配置的多个引脚，可以合并初始化**，代码更简洁。GPIO 时钟也只需使能一次。

### 踩坑记录

> **目标**：记录调试过程中遇到的实际问题及解决方法。

| 序号  | 问题现象                    | 原因分析                           | 解决方法                                                |
| --- | ----------------------- | ------------------------------ | --------------------------------------------------- |
| 1   | **按键完全没有响应**            | GPIO 时钟未使能                     | 确认 `__HAL_RCC_GPIOx_CLK_ENABLE()` 已调用               |
| 2   | **按键按下一次触发多次**          | 消抖延时不够或未调用                     | 在检测到按键后加入 `delay_ms(10)` 等待电平稳定                     |
| 3   | **按键逻辑反转（松开时触发）**       | 宏定义判断极性写反                      | 检查 `== GPIO_PIN_SET` 还是 `== GPIO_PIN_RESET`，与硬件电路匹配 |
| 4   | **编译报错 `GPI0_PIN` 未定义** | 拼写错误：`GPI0`（数字0）写成 `GPIO`（字母O） | 统一替换为 `GPIO`，注意字母 O 与数字 0 的区别                       |
| 5   | **未按下时按键状态随机跳变**        | 引脚悬空，未配置内部上下拉                  | 配置 `GPIO_PULLUP` 或 `GPIO_PULLDOWN` 给引脚确定的默认电平       |
| 6   | **多个按键同时按下只识别一个**       | 多个 `if` 判断中后面的覆盖前面的            | 若需组合键，改用特殊逻辑处理；若需优先级，调整判断顺序                         |
| 7   | **外接按键模块原理图与实测不符**      | 原理图可能看错，或模块内部有特殊电路             | **以万用表实测为准**，调整代码配置                                 |

#### 💡 核心理解纠正

> `KEY_R_STATUS` 宏只是**读取物理电平**（返回 0 或 1），它本身**不定义“按下”或“释放”的语义**。
> 
> **语义在扫描函数的判断条件中定义**：
> 
> - `if (KEY_R_STATUS == 0)` → 低电平被定义为“按下”
> 
> - `if (KEY_R_STATUS == 1)` → 高电平被定义为“按下”
> 
> 这种分层设计使得驱动更容易适配不同硬件：只需修改扫描函数中的判断条件，或修改宏定义中的比较对象（`SET`/`RESET`），即可切换高低电平有效。
