# 实验 25：FATFS文件系统

本实验通过 STM32F407ZGT6 的 **SDIO（Secure Digital Input/Output）** 接口驱动板载 **Micro SD 卡**，并移植 **FatFS 文件系统**，实现 SD 卡的 **文件创建、读写、删除、重命名、目录操作** 等功能。同时，通过 **SPI 接口** 驱动板载 **NOR Flash（W25Qxx）**，作为第二个磁盘。本实验使用 **USMART 串口调试组件** 进行交互式测试，所有文件系统操作均可通过串口命令直接执行，无需反复编译下载。通过本实验，深入理解 **SDIO 协议**、**FatFS 文件系统层级**、**多磁盘驱动架构**、**自定义内存池管理** 以及 **USMART 交互调试** 的应用。

## ② SD 卡基础概念与盘符映射

> **目标**：理解 SD 卡的基本结构、SDIO 通信协议以及 FATFS 文件系统的层级架构。

### SD 卡引脚定义（SDIO 模式）

| SD 卡引脚 | 名称       | 方向  | 功能                   |
| ------ | -------- | --- | -------------------- |
| **1**  | **DAT3** | 双向  | **数据线 3**（初始化时用作 CS） |
| **2**  | **CMD**  | 双向  | **命令/响应线**           |
| **3**  | VSS1     | 电源  | **GND**              |
| **4**  | VDD      | 电源  | **3.3V 电源**          |
| **5**  | CLK      | 输入  | **时钟信号**（由主机产生）      |
| **6**  | VSS2     | 电源  | **GND**              |
| **7**  | DAT0     | 双向  | **数据线 0**            |
| **8**  | DAT1     | 双向  | **数据线 1**            |
| **9**  | DAT2     | 双向  | **数据线 2**            |

### SDIO vs SPI 模式对比

| 对比项       | **SDIO 模式（本实验）**       | **SPI 模式**                  |
| --------- | ---------------------- | --------------------------- |
| **数据线宽度** | **4 位（D0~D3）**         | 1 位（MISO/MOSI）              |
| **传输速度**  | **快**（16MHz × 4 位）     | 慢（最高 25MHz × 1 位）           |
| **命令响应**  | 专用 CMD 线               | 共用 MOSI/MISO                |
| **引脚数量**  | 6 根（D0~D3 + CMD + CLK） | 4 根（CS + SCK + MOSI + MISO） |
| **硬件支持**  | 需要 SDIO 外设             | 任意 SPI 接口                   |
| **本实验使用** | ✅ **是**                | ❌                           |

### SD 卡类型

| 类型       | 容量范围       | 寻址方式     | 说明        |
| -------- | ---------- | -------- | --------- |
| **SDSC** | ≤ 2GB      | **字节寻址** | 标准容量卡（老卡） |
| **SDHC** | 4GB ~ 32GB | **扇区寻址** | 高容量卡（最常见） |
| **SDXC** | 64GB ~ 2TB | **扇区寻址** | 扩展容量卡     |

### SD 卡命令格式

```
SD 卡命令格式（48 位）：

  位 47~40  │  位 39~8  │  位 7~1  │  位 0
  ──────────┼───────────┼──────────┼─────────
  命令索引  │  参数     │   CRC7   │  停止位
  （6 位）  │ （32 位） │ （7 位） │ （1 位）
```

**常用命令**：

| 命令         | 值   | 响应类型 | 说明                        |
| ---------- | --- | ---- | ------------------------- |
| **CMD0**   | 0   | R1   | GO_IDLE_STATE（复位）         |
| **CMD8**   | 8   | R7   | SEND_IF_COND（电压检测）        |
| **CMD55**  | 55  | R1   | APP_CMD（前缀命令）             |
| **ACMD41** | 41  | R3   | SD_SEND_OP_COND（初始化）      |
| **CMD2**   | 2   | R2   | ALL_SEND_CID（获取CID）       |
| **CMD3**   | 3   | R6   | SEND_RELATIVE_ADDR（获取RCA） |
| **CMD9**   | 9   | R2   | SEND_CSD（获取CSD）           |
| **CMD7**   | 7   | R1b  | SELECT/DESELECT_CARD（选中卡） |
| **CMD17**  | 17  | R1   | READ_SINGLE_BLOCK（读单块）    |
| **CMD24**  | 24  | R1   | WRITE_SINGLE_BLOCK（写单块）   |
| **CMD13**  | 13  | R1   | SEND_STATUS（查询状态）         |

### 本实验盘符映射

| 盘符       | 硬件设备                   | 初始化函数           | 物理接口     | 备注          |
| -------- | ---------------------- | --------------- | -------- | ----------- |
| **`0:`** | **SD 卡**               | `sd_init()`     | SDIO（4位） | 本实验主要操作对象   |
| **`1:`** | **NOR Flash (W25Qxx)** | `W25QXX_Init()` | SPI1     | 板载 Flash 芯片 |

> ⚠️ **特别注意**：正点原子例程中 `0:` 对应 **SD卡**，`1:` 对应 **NOR Flash**，与部分开发板习惯相反。

## ③ 寄存器级

> **目标**：从寄存器层面理解 SDIO 接口的配置。

### SDIO 核心寄存器

| 寄存器            | 地址         | 作用         | 本实验配置            |
| -------------- | ---------- | ---------- | ---------------- |
| `SDIO_POWER`   | 0x40012C00 | 电源控制寄存器    | 使能 SDIO 电源       |
| `SDIO_CLKCR`   | 0x40012C04 | 时钟控制寄存器    | ClockDiv=1，上升沿采样 |
| `SDIO_CMD`     | 0x40012C0C | 命令寄存器      | 发送命令到 SD 卡       |
| `SDIO_RESPCMD` | 0x40012C10 | 响应命令索引     | 存储响应命令索引         |
| `SDIO_RESP1`   | 0x40012C14 | 响应寄存器1     | 短响应（R1/R3）       |
| `SDIO_RESP2`   | 0x40012C18 | 响应寄存器2     | 长响应（R2）          |
| `SDIO_DTIMER`  | 0x40012C24 | 数据超时寄存器    | 设置超时时间           |
| `SDIO_DLEN`    | 0x40012C28 | 数据长度寄存器    | 512 字节（块大小）      |
| `SDIO_DCTRL`   | 0x40012C2C | 数据传输控制寄存器  | 配置数据方向、块大小、传输模式  |
| `SDIO_STA`     | 0x40012C30 | 状态寄存器      | 中断标志位            |
| `SDIO_ICR`     | 0x40012C40 | 中断清除寄存器    | 写 1 清除对应标志       |
| `SDIO_FIFO`    | 0x40012C80 | FIFO 数据寄存器 | 32 位宽数据 FIFO     |

### SDIO 初始化流程

```
HAL_SD_Init() 内部流程：

  ① CMD0（复位）→ 等待 SD 卡进入空闲状态
  ② CMD8（电压检测）→ 检查 SD 卡是否支持 2.7~3.6V
  ③ ACMD41（初始化）→ 获取卡容量和类型
  ④ CMD2（获取 CID）→ 读取卡标识
  ⑤ CMD3（获取 RCA）→ 分配相对卡地址
  ⑥ CMD9（获取 CSD）→ 读取卡特定数据
  ⑦ CMD7（选择卡）→ 选中 SD 卡
```

## ⑤ 内存管理（自定义内存池）

> **目标**：理解本实验使用的自定义内存管理机制。

### 为什么要用自定义内存管理？

| 原因         | 说明                             |
| ---------- | ------------------------------ |
| **避免内存碎片** | 标准 `malloc` 在长时间运行后容易产生碎片      |
| **指定内存区域** | 可将不同数据放入不同内存池（SRAM/CCM/外部SRAM） |
| **提高速度**   | 固定块大小分配，速度快且时间可预测              |
| **裸机专用**   | 不依赖操作系统，适合单片机环境                |

### 三个内存池

| 内存池         | 位置      | 大小    | 特点                    |
| ----------- | ------- | ----- | --------------------- |
| **SRAMIN**  | 内部 SRAM | 100KB | CPU 和 DMA 都可访问（本实验使用） |
| **SRAMCCM** | CCM 内存  | 60KB  | **仅 CPU 可访问**，速度更快    |
| **SRAMEX**  | 外部 SRAM | 963KB | 容量大，速度较慢              |

### 内存分配原理

```
内存池（100KB = 3200 块，每块 32 字节）
┌────┬────┬────┬────┬────┬────┬─────┬────┐
│块0 │块1 │块2 │块3 │块4 │块5 │ ... │块3199│
└────┴────┴────┴────┴────┴────┴─────┴────┘

管理表（3200 项）
┌────┬────┬────┬────┬────┬────┬─────┬────┐
│ 0  │ 0  │ 0  │ 0  │ 0  │ 0  │ ... │ 0  │
└────┴────┴────┴────┴────┴────┴─────┴────┘
  ↑
 0 = 空闲，非 0 = 已分配（值代表连续块数）

分配 100 字节 → 需要 4 块（100/32 = 3.125 → 向上取整）
管理表：
┌────┬────┬────┬────┬────┬────┐
│ 4  │ 4  │ 4  │ 4  │ 0  │ 0  │
└────┴────┴────┴────┴────┴────┘
  ↑      ↑      ↑      ↑
 全部填 4（表示这 4 块属于同一个分配）
```

### 本实验中内存池的用途

| 用途             | 分配位置   | 大小     |
| -------------- | ------ | ------ |
| `fs[0]` 文件系统对象 | SRAMIN | ~数百字节  |
| `fs[1]` 文件系统对象 | SRAMIN | ~数百字节  |
| SD 卡读取缓冲区      | SRAMIN | 512 字节 |
| USMART 命令缓冲区   | SRAMIN | 数百字节   |

## ⑥ 中断/DMA 机制

> **目标**：理解 SDIO 的数据传输方式。

### 本实验的方案：**无中断，无 DMA，纯 CPU 轮询 + USART 中断**

| 机制            | 是否使用    | 说明                             |
| ------------- | ------- | ------------------------------ |
| **SDIO 中断**   | ❌ 否     | 使用轮询等待状态位（HAL_SD_GetCardState） |
| **SDIO DMA**  | ❌ 否     | 数据量小（512字节），轮询方式足够             |
| **USART1 中断** | ✅ **是** | 用于 USMART 命令接收                 |

### SDIO 传输状态机

```
HAL_SD_CARD_PROGRAMMING（编程中）
         │
         ▼
HAL_SD_CARD_RECEIVING（接收中）
         │
         ▼
HAL_SD_CARD_TRANSFER（传输完成，空闲）← ★ 轮询等待此状态
         │
         ▼
HAL_SD_CARD_READY（就绪）
```

### USART1 中断（USMART 使用）

```
void USART1_IRQHandler(void)
{
    if (__HAL_UART_GET_FLAG(&g_uart1_handle, UART_FLAG_RXNE) != RESET) {
        uint8_t data = (uint8_t)(g_uart1_handle.Instance->DR & 0xFF);
        usmart_dev.scan(data);   // USMART 命令扫描
    }
}
```

### 中断优先级配置建议

| 中断      | 抢占优先级 | 子优先级 | 说明          |
| ------- | ----- | ---- | ----------- |
| SysTick | 0     | 0    | 系统延时        |
| USART1  | 1     | 0    | USMART 串口命令 |
| DMA2    | 2     | 0    | 如开启 DMA 传输  |
| SDIO    | 3     | 0    | SD 卡中断      |

## ⑦ USMART 交互实验（核心章节）

> **目标**：通过 USMART 串口命令，逐条验证 FATFS 所有文件系统功能。

### 🧪 实验前准备

**前置条件**：

1. ✅ SD 卡已插入开发板

2. ✅ 开发板已上电，串口已连接（115200）

3. ✅ USMART 初始化成功（串口显示 `USMART Ready`）

4. ✅ SD 卡已挂载成功（`mf_scan_files("0:")` 返回 `0X0`）

**注意事项**：

- ⚠️ USMART **不能识别宏定义**（如 `FA_READ`），必须使用**数字值**

- ⚠️ `mf_write` 的第二个参数是**实际字节数**，不是字符串长度

- ⚠️ 每次操作后注意 `mf_close()` 释放文件句柄

---

### 📋 实验一：查看当前目录内容

**目的**：确认 SD 卡已挂载，查看根目录下的文件。

**执行命令**：

```
mf_scan_files("0:")
```

**预期结果**：

```
0:/System Volume Information
0:/FATFS.txt
=0X0
```

> 💡 **说明**：`0X0` = `FR_OK`，表示扫描成功。`System Volume Information` 是 Windows 自动创建的，可忽略。

### 📋 实验二：读取已存在的文件

**目的**：验证只读打开文件并读取内容。

**执行命令**：

## ⑧ 改参实验

### 改参实验 1：修改 SDIO 时钟频率

**操作**：在 `sd_init()` 中修改 `ClockDiv` 参数。

```
// 修改前（16MHz）
g_sd_handle.Init.ClockDiv = 1;

```

| ClockDiv | SDIO_CK   | 速度    | 稳定性           |
| -------- | --------- | ----- | ------------- |
| 0        | 24MHz     | 最快    | 部分旧卡不稳定       |
| **1**    | **16MHz** | **快** | **稳定（本实验默认）** |
| 2        | 12MHz     | 适中    | 稳定            |
| 4        | 8MHz      | 较慢    | 非常稳定          |

**结论**：SD 卡最高支持 24MHz，建议从 16MHz 开始测试。

## ⑨ 踩坑记录

### 坑1：`mf_scan_files("1:")` 返回 `0XC (FR_NOT_READY)`

**现象**：

```
mf_scan_files("1:") = 0XC
```

**原因**：

1. 未调用 `exfuns_init()` 分配文件系统对象

2. NOR Flash 硬件未初始化或不存在

3. `1:` 对应的底层驱动未正确实现

**解决**：

```
exfuns_init();           // 为 fs[0] 和 fs[1] 分配内存
f_mount(fs[1], "1:", 1); // 挂载 NOR Flash
```

### 坑2：格式化返回 `19 (FR_INT_ERR)`

**现象**：

```
格式化 1: 失败，错误码: 19
```

**原因**：

1. 格式化前未卸载（`f_mount(NULL, "1:", 1)`）

2. 底层 `disk_write` 未真正实现（只返回 0）

3. NOR Flash 扇区大小不匹配（512 vs 4096）

**解决**：

```
// 正确顺序
f_mount(NULL, "1:", 1);          // ① 先卸载
mf_fmkfs("1:", 0, 0);            // ② 再格式化
f_mount(fs[1], "1:", 1);         // ③ 重新挂载
```

**检查 `disk_write`**：

```
if (pdrv == 1) {
    // 必须真正写入，不能只 return 0
    return W25QXX_Write_Sector(...) ? RES_OK : RES_ERROR;
}
```

### 坑3：`mf_write` 写入数据长度错误

**现象**：

```
mf_write("Hello", 3)   // 只写了 "Hel"
```

**原因**：第二个参数是**实际要写入的字节数**，不是字符串长度。

**解决**：

```
mf_write("Hello", 5)              // 正确
mf_write("Hello\r\n", 7)          // 注意换行符
mf_write(str, strlen(str))        // 最保险
```

### 坑4：`mf_read` 读不到数据

**原因**：

1. 文件指针在末尾（先写后读未 `mf_lseek(0)`）

2. 读取长度超过文件实际大小

**解决**：

```
mf_open("0:/test.txt", 0x03)   // 读写模式
mf_lseek(0)                    // 指针移到开头
mf_read(100)
mf_close()
```

### 坑5：USMART 无法识别宏定义

**现象**：

```
mf_open("0:/test.txt", FA_READ)   // 报错：未知符号
```

**原因**：USMART 只解析数字，不解析 C 语言的宏定义。

**解决**：使用对应的数字值

```
mf_open("0:/test.txt", 0x01)      // FA_READ
mf_open("0:/test.txt", 0x0A)      // FA_WRITE | FA_CREATE_ALWAYS
mf_open("0:/test.txt", 0x32)      // FA_WRITE | FA_OPEN_APPEND
```

### 坑6：格式化后依然看到旧文件

**原因**：

1. 格式化后未重新挂载（缓存未刷新）

2. 格式化了错误的盘符

**解决**：

```
f_mount(NULL, "0:", 1);      // 先卸载
mf_fmkfs("0:", 0, 0);        // 格式化
f_mount(fs[0], "0:", 1);     // 重新挂载
mf_scan_files("0:");         // 重新扫描
```

### 坑7：`mf_fmkfs` 第三个参数含义混淆

**现象**：

```
mf_fmkfs("0:", 0, 4096)   // 错误：4096被解释为簇扇区数
```

**原因**：第三个参数 `au` 是**簇扇区数**，不是字节数。

**正确理解**：

| 传入值  | 实际含义    | 簇大小（512B扇区） |
| ---- | ------- | ----------- |
| `0`  | 自动选择    | 自动          |
| `8`  | 8个扇区/簇  | 4KB         |
| `16` | 16个扇区/簇 | 8KB         |
| `32` | 32个扇区/簇 | 16KB        |

**正确用法**：

```
mf_fmkfs("0:", 0, 0)    // 自动选择（推荐）
mf_fmkfs("0:", 0, 8)    // 4KB簇
```

### 坑8：正点原子例程中 `0:` 和 `1:` 的对应关系混淆

| 盘符   | 硬件            | 容易误认为     |
| ---- | ------------- | --------- |
| `0:` | **SD卡**       | NOR Flash |
| `1:` | **NOR Flash** | SD卡       |

**注意**：格式化时别搞错盘符！

---

### 坑9：`mf_rename` 返回 `FR_INVALID_NAME`

**原因**：

1. 新文件名包含非法字符（`/`, `:`, `*`, `?` 等）

2. 新文件名已存在

**解决**：使用合法文件名

```
mf_rename("0:/FATFS.txt", "0:/RENAMED.txt")  // 合法
```

### 坑10：`mf_unlink` 无法删除非空目录

**现象**：

```
mf_unlink("0:/TESTDIR")  // 返回错误
```

**原因**：FatFS 要求目录必须为空才能删除。

**解决**：

```
mf_unlink("0:/TESTDIR/file1.txt")   // 先删文件
mf_unlink("0:/TESTDIR/file2.txt")
mf_unlink("0:/TESTDIR")             // 再删目录
```

## 📌 实验总结

| 模块         | 关键点                                 |
| ---------- | ----------------------------------- |
| **时钟**     | SDIO 需要 16MHz，系统主频 168MHz           |
| **SDIO**   | 4 位数据线，16MHz 时钟，轮询方式                |
| **FATFS**  | `0:` 对应 SD 卡，`1:` 对应 NOR Flash      |
| **USMART** | 参数用数字，不能用宏定义                        |
| **格式化**    | 先卸载 → 格式化 → 重新挂载                    |
| **踩坑**     | `FR_INT_ERR(19)` = `disk_write` 未实现 |
