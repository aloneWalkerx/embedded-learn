# 实验 14：DMA传输

本实验通过 STM32F407ZGT6 的 **DMA2（Direct Memory Access）** 控制器，实现 **USART1 的大数据量发送**。核心原理是利用 DMA 硬件自动搬运数据，**彻底释放 CPU**，让 CPU 在数据传输期间可以并行处理其他任务（如 LED 闪烁、按键扫描、LCD 刷新等）。这是嵌入式系统中 **“CPU 与外设并行工作”** 的经典范例。

> **核心区别**：DMA 是**唯一一个与 CPU 同频（168MHz）且能独立访问总线的外设**，因此数据传输效率极高，是实现 CPU 与外设并行工作的关键。

### ② 寄存器级

> **目标**：从寄存器层面理解 DMA 的工作原理。

#### DMA 核心寄存器

| 寄存器            | 作用             | 本实验配置                              |
| -------------- | -------------- | ---------------------------------- |
| **DMA_SxCR**   | 数据流控制寄存器       | 配置通道、方向、优先级、传输模式、数据宽度、地址递增模式       |
| **DMA_SxNDTR** | 数据流传输数量寄存器     | 设置要传输的字节数（`sizeof(buf)` ≈ 7000 字节） |
| **DMA_SxPAR**  | 外设地址寄存器        | 设置为 `&USART1->DR`（USART1 的数据寄存器地址） |
| **DMA_SxM0AR** | 内存地址寄存器 0      | 设置为 `buf`（数据缓冲区的起始地址）              |
| **DMA_SxFCR**  | 数据流 FIFO 控制寄存器 | 禁用 FIFO（直接模式）                      |
| **DMA_LISR**   | 低中断状态寄存器       | 读取 Stream0~3 的中断标志位                |
| **DMA_HISR**   | 高中断状态寄存器       | 读取 Stream4~7 的中断标志位                |

#### DMA 传输流程（硬件自动完成）

┌──────────────────────────────────────────────────────────────────────────────┐
│                    DMA 传输硬件流程（无需 CPU 干预）                         │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  CPU 配置阶段：                                                              │
│  ┌─────────────────────────────────────────────────────────────────────┐    │
│  │  ① 设置 DMA_SxPAR  = &USART1->DR  （外设地址）                     │    │
│  │  ② 设置 DMA_SxM0AR = buf           （内存地址）                     │    │
│  │  ③ 设置 DMA_SxNDTR = sizeof(buf)   （传输字节数）                   │    │
│  │  ④ 配置 DMA_SxCR  （方向、宽度、优先级等）                         │    │
│  │  ⑤ 使能 DMA_SxCR 的 EN 位（启动 DMA）                              │    │
│  └─────────────────────────────────────────────────────────────────────┘    │
│                                    │                                        │
│                                    ▼                                        │
│  DMA 硬件自动执行阶段（无需 CPU 参与）：                                    │
│  ┌─────────────────────────────────────────────────────────────────────┐    │
│  │  Step 1: 从内存地址（buf[0]）读取 1 字节                           │    │
│  │          DMA_SxM0AR 自动 +1（地址递增）                           │    │
│  │          DMA_SxNDTR 自动 -1（剩余计数减 1）                        │    │
│  │          ↓                                                         │    │
│  │  Step 2: 将该字节写入外设地址（USART1->DR）                        │    │
│  │          DMA_SxPAR 保持不变（外设地址不递增）                      │    │
│  │          ↓                                                         │    │
│  │  Step 3: USART1 硬件自动将 DR 中的数据发送出去                     │    │
│  │          ↓                                                         │    │
│  │  Step 4: 等待 USART1 发送完成（硬件自动等待 TXE 标志）             │    │
│  │          ↓                                                         │    │
│  │  Step 5: 重复 Step 1~4，直到 DMA_SxNDTR = 0                       │    │
│  │          ↓                                                         │    │
│  │  Step 6: 触发传输完成中断（TCIF 标志置位）                         │    │
│  │          ↓                                                         │    │
│  │  Step 7: 调用 HAL_UART_TxCpltCallback（用户回调）                  │    │
│  └─────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  ★ 关键特性：DMA 传输期间 CPU 完全自由！                                    │
│    只有 Step 7（传输完成）才触发中断，CPU 才参与。                          │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

#### DMA 通道映射（USART1）

| 外设功能          | 方向      | DMA1 | DMA2                  |
| ------------- | ------- | ---- | --------------------- |
| **USART1_TX** | 内存 → 外设 | -    | **Stream7, Channel4** |
| **USART1_RX** | 外设 → 内存 | -    | **Stream5, Channel4** |

> **注意**：USART1 的 TX 和 RX **只能使用 DMA2**，不能用 DMA1。这是硬件固定映射，不可更改。

### ③ 数据流

> **目标**：理清从“按键触发”到“串口数据发送完成”的完整链路。

┌──────────────────────────────────────────────────────────────────────────────┐
│                    DMA 串口发送完整数据流                                    │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  【用户交互层】                                                              │
│                                                                              │
│  用户按下 KEY0 → key_i_scan() 检测到按键                                    │
│       │                                                                      │
│       ▼                                                                      │
│  if (uart_ready == 1) → 允许发送                                            │
│       │                                                                      │
│       ▼                                                                      │
│  uart_ready = 0  （互斥锁：锁定，防止重复触发）                              │
│       │                                                                      │
│       ▼                                                                      │
│  HAL_UART_Transmit_DMA(&g_uart1_handle, buf, sizeof(buf))                   │
│                                                                              │
│  【HAL 库层】                                                                 │
│                                                                              │
│  HAL_UART_Transmit_DMA() 内部操作：                                          │
│       │                                                                      │
│       ├── ① 设置 DMA_SxM0AR = buf（内存地址）                               │
│       ├── ② 设置 DMA_SxPAR = &USART1->DR（外设地址）                        │
│       ├── ③ 设置 DMA_SxNDTR = sizeof(buf)（传输字节数）                     │
│       ├── ④ 使能 DMA 数据流（EN 位 = 1）                                    │
│       └── ⑤ 立即返回（不等待传输完成）                                      │
│                                                                              │
│  【DMA 硬件层】（自动运行，CPU 并行执行其他任务）                            │
│                                                                              │
│  DMA 控制器循环执行：                                                        │
│       │                                                                      │
│       ├── buf[0] → USART1->DR → 串口发送                                    │
│       ├── buf[1] → USART1->DR → 串口发送                                    │
│       ├── ...                                                               │
│       └── buf[N-1] → USART1->DR → 串口发送                                  │
│           │                                                                  │
│           └── NDTR 减到 0 → TCIF 标志置位 → 触发中断                        │
│                                                                              │
│  【中断处理层】                                                              │
│                                                                              │
│  DMA2_Stream7_IRQHandler() → HAL_DMA_IRQHandler()                           │
│       │                                                                      │
│       ├── 清除 TCIF 中断标志位                                               │
│       │                                                                      │
│       └── 调用 HAL_DMA_TxCpltCallback()                                     │
│           │                                                                  │
│           ▼                                                                  │
│  HAL_UART_TxCpltCallback() → uart_ready = 1（解锁）                         │
│                                                                              │
│  ★ 在 DMA 传输期间，CPU 在做什么？                                          │
│    ① LED0 持续闪烁（每 200ms 翻转一次）                                     │
│    ② 按键扫描持续进行（可检测 KEY0，只是被 uart_ready 阻止重复启动）        │
│    ③ LCD 持续显示                                                           │
│    ④ CPU 可以处理任何其他任务（如 ADC 采样、PWM 输出等）                    │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

### ④ 中断机制

> **目标**：理解 DMA 传输完成中断的触发与处理流程。

#### 本实验的中断方案

| 中断类型                    | 触发条件                   | 处理函数                      | 作用                      |
| ----------------------- | ---------------------- | ------------------------- | ----------------------- |
| **DMA2_Stream7 传输完成中断** | DMA 发送完所有数据（NDTR 减到 0） | `HAL_UART_TxCpltCallback` | 解锁 `uart_ready`，允许下一次发送 |

### ⑤ 改参实验

> **目标**：通过修改参数验证对 DMA 功能的理解。

#### 改参实验 1：修改 DMA 传输模式（普通 → 循环）

**操作**：在 `dma.c` 中修改 `Mode` 参数。



// 修改前
g_dma_handle.Init.Mode = DMA_NORMAL;
// 修改后
g_dma_handle.Init.Mode = DMA_CIRCULAR;

**现象**：启动一次传输后，DMA 会**不断循环发送** `buf` 中的数据（发送完最后一字节后自动从头开始）。

**结论**：循环模式适合**持续数据流**（如 ADC 连续采样、音频播放等）。

---

#### 改参实验 2：修改传输数据量

**操作**：在 `main.c` 中修改 `buf` 的重复次数。

// 修改前：重复 200 次（约 7000 字节）
for (buf_index = 0; buf_index < 200; buf_index++)
// 修改后：重复 10 次（约 350 字节）
for (buf_index = 0; buf_index < 10; buf_index++)

**现象**：发送的数据量变小，传输时间变短。

**结论**：DMA 可以灵活适应**任意数据量**的传输，数据量越大，DMA 的优势越明显。

---

#### 改参实验 3：修改 DMA 数据宽度

**操作**：在 `dma.c` 中修改数据宽度，并将 `buf` 改为 `uint16_t` 数组。

// 修改前
g_dma_handle.Init.PeriphDataAlignment = DMA_PDATAALIGN_BYTE;
g_dma_handle.Init.MemDataAlignment = DMA_MDATAALIGN_BYTE;
// 修改后
g_dma_handle.Init.PeriphDataAlignment = DMA_PDATAALIGN_HALFWORD;
g_dma_handle.Init.MemDataAlignment = DMA_MDATAALIGN_HALFWORD;

**现象**：DMA 每次传输 2 字节（16 位），传输速度翻倍。

**结论**：数据宽度必须与**外设数据寄存器宽度**匹配，否则数据传输会出错。

---

#### 改参实验 4：修改 DMA 传输方向（内存 → 内存）

**操作**：在 `dma.c` 中修改 `Direction` 参数，并配置两个内存地址。

// 修改方向
g_dma_handle.Init.Direction = DMA_MEMORY_TO_MEMORY;
// 注意：内存到内存模式只能用 DMA2，且不需要外设请求
// 需要在 HAL_DMA_Start() 中指定源地址和目标地址
HAL_DMA_Start(&g_dma_handle, (uint32_t)src, (uint32_t)dst, size);

**现象**：DMA 将 `src` 数组的数据复制到 `dst` 数组。

**结论**：DMA2 支持**内存到内存**传输，可用于快速数组拷贝、图像处理等场景。

---

#### 改参实验 5：修改 `uart_ready` 互斥锁逻辑

**操作**：在 `main.c` 中移除 `uart_ready` 检查。

// 修改前
if (uart_ready == 1) {
    uart_ready = 0;
    HAL_UART_Transmit_DMA(...);
}
// 修改后（危险！）
HAL_UART_Transmit_DMA(...);  // 不检查就直接启动

**现象**：快速连按 KEY0 时，DMA 传输出现**数据错乱**或**硬件错误**。

**结论**：`uart_ready` 互斥锁是**保护 DMA 资源的必要机制**，防止多个传输请求同时操作同一个数据流。
