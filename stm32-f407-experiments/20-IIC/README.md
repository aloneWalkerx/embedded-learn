# 实验 20：I2C通信

本实验通过 **模拟 IIC（软件 IIC）** 方式，使用 STM32F407 的 GPIO（PB8、PB9）与 **AT24C02 EEPROM** 芯片进行通信，实现了数据的写入与读取。通过本实验，深入理解 IIC 总线协议的**起始/停止/应答/数据收发**等核心时序，以及 **开漏输出 + 上拉电阻** 的硬件原理。

### ① 时钟树

> **目标**：理解模拟 IIC 的时钟来源与依赖。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    STM32F407 时钟树（模拟 IIC 部分）                        │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  本实验使用模拟 IIC，不依赖硬件 I2C 外设，因此无需配置 I2C 时钟。            │
│  通信时序完全由软件控制，依赖以下两个因素：                                   │
│                                                                              │
│  【CPU 执行速度】                                                           │
│  ┌──────────────────────────────────────────────────────────────────────┐    │
│  │  系统时钟 168MHz → 每条指令执行速度极快                             │    │
│  │  delay_us(2) 产生约 2µs 的延时 → SCL 频率约 250kHz                 │    │
│  └──────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  【GPIO 翻转速度】                                                          │
│  ┌──────────────────────────────────────────────────────────────────────┐    │
│  │  GPIO 挂载在 APB2（84MHz）上                                       │    │
│  │  开漏输出模式下，翻转速度受限于外部上拉电阻和总线电容                │    │
│  └──────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  ★ 与硬件 IIC 的区别：                                                      │
│     - 硬件 IIC：由外设自动产生时序，CPU 仅需配置寄存器                      │
│     - 模拟 IIC：由 CPU 逐位控制 GPIO 电平，时序完全由软件控制               │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  关键配置：                                                                  │
│  ┌─────────────────────┬────────────────────────────────────────────────┐   │
│  │ SCL 引脚            │ PB8（GPIOB）                                  │   │
│  │ SDA 引脚            │ PB9（GPIOB）                                  │   │
│  │ GPIO 模式           │ 开漏输出（GPIO_MODE_OUTPUT_OD）               │   │
│  │ 上拉电阻            │ 外部 4.7kΩ → 3.3V                            │   │
│  │ 通信速率            │ 约 250kHz（由 delay_us(2) 决定）              │   │
│  │ EEPROM 型号         │ AT24C02（256 字节）                           │   │
│  │ EEPROM 设备地址     │ 0xA0（写）/ 0xA1（读）                       │   │
│  └─────────────────────┴────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────────────────┘
```

### ② 寄存器级

> **目标**：从寄存器层面理解模拟 IIC 的工作原理。

#### 核心寄存器

| 寄存器/宏            | 作用      | 本实验操作                                |
| ---------------- | ------- | ------------------------------------ |
| **GPIOB_MODER**  | 引脚模式寄存器 | 设置为开漏输出模式（`GPIO_MODE_OUTPUT_OD`）     |
| **GPIOB_OTYPER** | 输出类型寄存器 | 开漏输出（`GPIO_OTYPE_OD`）                |
| **GPIOB_ODR**    | 输出数据寄存器 | `IIC_SCL(1/0)`、`IIC_SDA(1/0)` 操作此寄存器 |
| **GPIOB_IDR**    | 输入数据寄存器 | `IIC_SDA_READ` 读取此寄存器                |

#### 开漏输出原理

```
开漏输出内部结构：

     VDD（3.3V）
        │
       ║ 上拉电阻（4.7kΩ，外接）
        │
        └─────→ 引脚（SDA/SCL）
        │
       ║ N-MOS 管（内部开关）
        │
       GND

写 0：N-MOS 管导通 → 引脚被拉到 GND（低电平）
写 1：N-MOS 管截止 → 引脚被“释放”（高阻态）→ 上拉电阻拉高（高电平）
```

#### IIC 协议时序

| 信号            | 时序                      | 代码实现                   |
| ------------- | ----------------------- | ---------------------- |
| **起始（START）** | SCL=1，SDA 从 1→0         | `iic_start()`          |
| **停止（STOP）**  | SCL=1，SDA 从 0→1         | `iic_stop()`           |
| **发送 bit**    | SCL=0 时改变 SDA，SCL=1 时锁存 | `iic_send_byte()`      |
| **读取 bit**    | SCL=1 时读取 SDA           | `iic_read_byte()`      |
| **应答（ACK）**   | 在第 9 个时钟，SDA=0          | `iic_wait_ack()`（主机检测） |

### ③ 数据流

> **目标**：理清“写入数据到 EEPROM”和“从 EEPROM 读取数据”的完整流程。

#### 写操作完整流程（以 `at24cxx_write_one_byte(addr, data)` 为例）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    AT24C02 写操作完整数据流                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ① 主机发送起始信号（iic_start）                                           │
│     └── SCL=1 时 SDA 从 1→0 跳变                                          │
│                                                                             │
│  ② 主机发送设备地址（写方向 0xA0）（iic_send_byte）                        │
│     └── 从机比对地址，确认是自己的地址                                     │
│                                                                             │
│  ③ 从机应答（iic_wait_ack）                                                │
│     └── 从机主动拉低 SDA = 0                                               │
│                                                                             │
│  ④ 主机发送要写入的地址（addr）（iic_send_byte）                           │
│     └── 从机收到地址，准备接收数据                                         │
│                                                                             │
│  ⑤ 从机应答（iic_wait_ack）                                                │
│     └── 从机主动拉低 SDA = 0                                               │
│                                                                             │
│  ⑥ 主机发送要写入的数据（data）（iic_send_byte）                           │
│     └── 从机收到数据，存入内部缓冲区                                       │
│                                                                             │
│  ⑦ 从机应答（iic_wait_ack）                                                │
│     └── 从机主动拉低 SDA = 0                                               │
│                                                                             │
│  ⑧ 主机发送停止信号（iic_stop）                                            │
│     └── SCL=1 时 SDA 从 0→1 跳变                                          │
│                                                                             │
│  ⑨ 等待 EEPROM 内部编程（delay_ms(10)）                                   │
│     └── EEPROM 将数据烧写到 Flash（5~10ms）                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 读操作完整流程（以 `at24cxx_read_one_byte(addr)` 为例）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    AT24C02 读操作完整数据流                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【阶段一：伪写（告诉 EEPROM 要读哪个地址）】                               │
│                                                                             │
│  ① 主机发送起始信号（iic_start）                                           │
│  ② 主机发送设备地址（写方向 0xA0）（iic_send_byte）                        │
│  ③ 从机应答（iic_wait_ack）                                                │
│  ④ 主机发送要读取的地址（addr）（iic_send_byte）                           │
│  ⑤ 从机应答（iic_wait_ack）                                                │
│                                                                             │
│  【阶段二：重复起始 + 真读】                                                │
│                                                                             │
│  ⑥ 主机发送重复起始信号（iic_start）                                       │
│     └── 不发送 STOP，直接再次 START                                        │
│                                                                             │
│  ⑦ 主机发送设备地址（读方向 0xA1）（iic_send_byte）                        │
│  ⑧ 从机应答（iic_wait_ack）                                                │
│                                                                             │
│  ⑨ ★ 从机发送数据（iic_read_byte）                                        │
│     └── 从机驱动 SDA，主机读取 8 个 bit                                    │
│                                                                             │
│  ⑩ 主机发送 NACK（iic_nack）                                               │
│     └── 告诉从机：“读完这个字节了，不要再发了”                             │
│                                                                             │
│  ⑪ 主机发送停止信号（iic_stop）                                            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### SDA 控制权切换

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    SDA 控制权切换时序                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  阶段           │ 谁控制 SDA     │ 做什么                                   │
│  ───────────────┼────────────────┼─────────────────────────────────────────│
│  起始信号        │ 主机           │ 主动拉低 SDA                           │
│  发送地址/数据   │ 主机           │ 逐位设置 SDA 电平                      │
│  等待应答        │ ★ 从机        │ 从机主动拉低 SDA（应答）               │
│  读取数据        │ ★ 从机        │ 从机驱动 SDA 发送 bit                  │
│  主机 NACK       │ 主机           │ 释放 SDA（保持高电平）                 │
│  停止信号        │ 主机           │ 主动拉高 SDA                           │
│                                                                             │
│  ★ 主机必须“释放 SDA”后，从机才能控制 SDA                                 │
│    释放 = IIC_SDA(1) = 断开内部 MOS 管                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### ④ 中断/DMA 机制

> **目标**：理解本实验的通信方式。

#### 本实验的方案：**无中断，无 DMA，纯轮询（模拟 IIC）**

| 机制      | 是否使用 | 说明                             |
| ------- | ---- | ------------------------------ |
| **中断**  | 否    | 所有时序由 `delay_us()` 控制，CPU 全程参与 |
| **DMA** | 否    | 逐位发送/读取，数据量小（EEPROM 读写），无需 DMA |

#### 与硬件 IIC 的对比

| 对比项        | 模拟 IIC（本实验）                | 硬件 IIC（STM32 外设）   |
| ---------- | -------------------------- | ------------------ |
| **实现方式**   | 软件控制 GPIO 翻转               | 硬件外设自动产生时序         |
| **CPU 占用** | 高（每 bit 都要参与）              | 低（配置后自动运行）         |
| **速度**     | 由 `delay_us()` 控制（~250kHz） | 由时钟配置决定（最高 400kHz） |
| **代码量**    | 较多（需手写时序）                  | 较少（调用 HAL 库函数）     |
| **灵活性**    | 高（任意 GPIO 都可使用）            | 低（必须使用 I2C 复用引脚）   |
| **适用场景**   | 学习原理、引脚受限                  | 实际产品开发             |

### ⑤ 改参实验

#### 改参实验 1：修改 IIC 通信速率

**操作**：在 `iic_delay()` 中修改延时值。

```
// 修改前（2µs）
static void iic_delay(void) { delay_us(2); }
// 修改后（1µs，更快）
static void iic_delay(void) { delay_us(1); }
// 修改后（5µs，更慢但更稳定）
static void iic_delay(void) { delay_us(5); }
```

**现象**：

- 延时越短，通信速度越快，但可能因从机反应不过来而失败

- 延时越长，通信越稳定，但速度变慢

**结论**：需根据从机规格和总线负载选择合适的速率。

---

#### 改参实验 2：修改 EEPROM 型号

**操作**：在 `24cxx.h` 中修改 `EE_TYPE` 宏。

```
// 修改前（AT24C02，256 字节）
#define EE_TYPE AT24C02
// 修改后（AT24C16，2048 字节）
#define EE_TYPE AT24C16
```

**现象**：容量变化，地址范围扩大。

**结论**：更换芯片时，只需修改型号宏定义，驱动代码兼容（地址用 `uint16_t`）。

---

#### 改参实验 3：修改 IIC 引脚

**操作**：在 `iic.h` 中修改引脚宏定义。

```
// 修改前（PB8、PB9）
#define IIC_SCL_GPIO_PIN GPIO_PIN_8
#define IIC_SDA_GPIO_PIN GPIO_PIN_9
// 修改后（PA5、PA6）
#define IIC_SCL_GPIO_PIN GPIO_PIN_5
#define IIC_SDA_GPIO_PIN GPIO_PIN_6
```

**现象**：通信切换到新的引脚。

**结论**：模拟 IIC 可使用任意 GPIO，只需修改宏定义即可。

---

#### 改参实验 4：修改写入后延时

**操作**：在 `at24cxx_write_one_byte()` 中修改延时。

```
// 修改前（10ms）
delay_ms(10);
// 修改后（5ms，更快但可能不稳定）
delay_ms(5);
// 修改后（15ms，更稳定但更慢）
delay_ms(15);
```

**现象**：

- 延时 5ms：写入可能失败（EEPROM 还没完成编程）

- 延时 15ms：写入稳定，但速度变慢

**结论**：延时时间需 ≥ EEPROM 最大编程时间（参考数据手册）。
