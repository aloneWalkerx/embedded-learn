# 实验 12：RTC时钟（带闹钟与周期唤醒）

本实验通过 STM32F407ZGT6 的 **RTC 外设（Real-Time Clock）**，实现实时时钟，并扩展了 **闹钟中断** 和 **周期唤醒中断** 功能。RTC 由 **LSE（32.768kHz 外部晶振）** 驱动，自己焊接了一颗纽扣电池，在主电源掉电后由 VBAT 纽扣电池继续供电计时。实验还集成了 **有源蜂鸣器** 作为闹钟输出，并通过 **USMART 组件** 实现时间/闹钟的串口调试设置（====底部有实验结果====）。

### ② 寄存器级

> **目标**：从寄存器层面理解 RTC 的工作原理与配置。

#### RTC 核心寄存器

| 寄存器             | 作用              | 本实验配置                                     |
| --------------- | --------------- | ----------------------------------------- |
| **RTC_CR**      | 控制寄存器           | 使能 RTC、配置 24 小时制、使能闹钟/唤醒中断                |
| **RTC_TR**      | 时间寄存器           | 存储时/分/秒（BCD 码），通过 `HAL_RTC_SetTime` 写入    |
| **RTC_DR**      | 日期寄存器           | 存储年/月/日/星期（BCD 码），通过 `HAL_RTC_SetDate` 写入 |
| **RTC_SSR**     | 亚秒寄存器           | 高精度时间（未使用）                                |
| **RTC_PRER**    | 预分频寄存器          | AsynchPrediv=127，SynchPrediv=255          |
| **RTC_ALRMAR**  | 闹钟 A 寄存器        | 存储闹钟时分秒和星期匹配值                             |
| **RTC_WUTR**    | 唤醒定时器寄存器        | 唤醒计数值（0~65535）                            |
| **RTC_ISR**     | 中断状态寄存器         | 读取闹钟匹配标志、唤醒标志                             |
| **RTC_BKP_DRx** | 备份数据寄存器（x=0~19） | 存储配置标记（0x5050 / 0x5051）                   |

#### RTC 时间/日期存储格式（BCD 码）

RTC 内部使用 **BCD 编码**（Binary-Coded Decimal）存储时间/日期，每位十进制数用 4 位二进制表示：

| 字段    | 寄存器位      | 示例（14:30:25） |
| ----- | --------- | ------------ |
| 秒（个位） | TR[3:0]   | 0x5          |
| 秒（十位） | TR[7:4]   | 0x2          |
| 分（个位） | TR[11:8]  | 0x0          |
| 分（十位） | TR[15:12] | 0x3          |
| 时（个位） | TR[19:16] | 0x4          |
| 时（十位） | TR[21:20] | 0x1          |

`HAL_RTC_SetTime` 的 `RTC_FORMAT_BIN` 参数会自动完成二进制 ↔ BCD 转换。

### ④ 中断/DMA 机制

> **目标**：理解 RTC 的两种中断及其应用。

#### 本实验的中断方案

| 中断类型         | 触发条件           | 回调/处理函数                              | 作用             |
| ------------ | -------------- | ------------------------------------ | -------------- |
| **RTC 闹钟中断** | 当前时间匹配闹钟 A 设置  | `HAL_RTC_AlarmAEventCallback`        | 串口打印 + 设置蜂鸣器标志 |
| **RTC 唤醒中断** | 唤醒定时器溢出（1 秒周期） | `HAL_RTCEx_WakeUpTimerEventCallback` | 翻转 LED1，指示系统运行 |

#### 与前面实验的中断对比

| 实验             | 中断类型                    | 中断频率           | 主要用途               |
| -------------- | ----------------------- | -------------- | ------------------ |
| 实验 5（基本定时器）    | TIM6 更新中断               | 可配置（如 500ms）   | 周期性任务调度            |
| 实验 6（PWM 输出）   | 无中断（纯硬件输出）              | -              | 生成 PWM 波形          |
| 实验 7（输入捕获）     | TIM5 捕获中断 + 更新中断        | 每个边沿触发         | 测量信号脉宽             |
| 实验 8（脉冲计数）     | TIM2 更新中断（溢出时）          | 约 65535 个脉冲    | 扩展计数范围             |
| 实验 9（TFTLCD）   | 无中断（纯 CPU 轮询）           | -              | 驱动 8080 接口彩屏       |
| 实验 10（USMART）  | USART1 接收中断 + TIM4 更新中断 | 每个字节 + 1ms     | 接收串口命令 + 定时扫描执行    |
| **实验 11（RTC）** | **RTC 闹钟中断 + RTC 唤醒中断** | **按设置触发 + 1秒** | **时间匹配提醒 + 周期性任务** |

> **核心特点**：RTC 中断由 **独立的低速时钟域（LSE/LSI）** 驱动，即使 CPU 处于休眠模式（低功耗状态），RTC 中断仍能唤醒系统，适合低功耗应用。

#### 中断配置要点

// 闹钟中断配置（在 rtc_set_alarm 中）
HAL_NVIC_SetPriority(RTC_Alarm_IRQn, 0, 0);  // 最高抢占优先级
HAL_NVIC_EnableIRQ(RTC_Alarm_IRQn);
// 唤醒中断配置（在 rtc_set_wakeup 中）
HAL_NVIC_SetPriority(RTC_WKUP_IRQn, 0, 0);
HAL_NVIC_EnableIRQ(RTC_WKUP_IRQn);



### ⑤ 改参实验

> **目标**：通过修改参数验证对 RTC 外设的理解。

#### 改参实验 1：修改唤醒周期

**操作**：在 `rtc_set_wakeup` 中修改 `count` 参数。

rtc_set_wakeup(RTC_WAKEUPCLOCK_CK_SPRE_16BITS, 2);  // 2 秒
rtc_set_wakeup(RTC_WAKEUPCLOCK_CK_SPRE_16BITS, 5);  // 5 秒

**现象**：LED1 翻转周期变为 2 秒或 5 秒。

**结论**：`count` 值决定唤醒周期，单位为 1 秒（当使用 `CK_SPRE` 时钟源时）。

---

#### 改参实验 2：修改闹钟匹配模式

**操作**：在 `rtc_set_alarm` 中修改 `AlarmMask` 参数。

| 修改前                  | 修改后                     | 效果              |
| -------------------- | ----------------------- | --------------- |
| `RTC_ALARMMASK_NONE` | `RTC_ALARMMASK_SECONDS` | 屏蔽秒字段，每分钟触发一次   |
| `RTC_ALARMMASK_NONE` | `RTC_ALARMMASK_HOURS`   | 屏蔽小时字段，每天同一分钟触发 |

**现象**：闹钟触发频率改变。

**结论**：`AlarmMask` 可以控制闹钟的精确匹配粒度，实现每分钟/每小时/每天触发的闹钟。

---

#### 改参实验 3：修改 RTC 时钟源（LSE → LSI）

**操作**：在 `HAL_RTC_MspInit` 中强制使用 LSI（注释掉 LSE 尝试分支）。

// 直接强制使用 LSI
rcc_osc_init_struct.OscillatorType = RCC_OSCILLATORTYPE_LSI;
rcc_osc_init_struct.LSIState = RCC_LSI_ON;
// ...
rcc_periph_clk_init_struct.RTCClockSelection = RCC_RTCCLKSOURCE_LSI;

**现象**：RTC 时间走时精度变差（每天可能快/慢几秒到几分钟）。

**结论**：LSE（外部晶振）精度远高于 LSI（内部 RC），对时间精度要求高的应用必须使用 LSE。

---

#### 改参实验 4：修改默认时间/日期

**操作**：在 `rtc_init()` 中修改默认时间设置

rtc_set_time(0, 0, 0, 0);   // 改为 00:00:00
rtc_set_date(24, 1, 1, 1);  // 改为 2024-01-01 周一

**现象**：第一次烧录或电池掉电后，RTC 初始化为新的默认时间。

**结论**：默认时间应在代码中根据实际需求设置。

---

#### 改参实验 5：修改蜂鸣器响铃时长

**操作**：在 `rtc.c` 的 `HAL_RTC_AlarmAEventCallback` 中修改 `g_buzzer_count` 值。

g_buzzer_count = 20;  // 响 10 秒（20 次 × 500ms）

**现象**：闹钟触发后蜂鸣器响铃时间变化。

**结论**：通过调整 `g_buzzer_count` 可以灵活控制响铃时长



### ⑥ 踩坑记录

| 问题现象                    | 原因                                 | 解决方法                                         |
| ----------------------- | ---------------------------------- | -------------------------------------------- |
| RTC 时间不走（一直不变）          | LSE 晶振未起振                          | 检查开发板是否有 32.768kHz 晶振；代码中已自动切换 LSI           |
| 第一次上电时间不更新              | 备份寄存器读取在 `HAL_RTC_Init` 之前         | 调整顺序：先 `HAL_RTC_Init`，再 `rtc_read_bkr`       |
| 闹钟不触发                   | 未使能闹钟中断或 NVIC 未配置                  | 检查 `HAL_NVIC_EnableIRQ(RTC_Alarm_IRQn)` 是否执行 |
| 蜂鸣器在中断中死循环              | 在中断回调中使用了 `delay_ms`               | **改用标志位方案**，在主循环中处理蜂鸣器逻辑                     |
| 唤醒中断触发频率异常高             | `count = 0` 导致立即触发并持续触发            | 改为 `count = 1`（1 秒周期）                        |
| `HAL_RTC_GetDate` 返回值不变 | 未先调用 `HAL_RTC_GetTime`             | 必须先调用 `GetTime` 再调用 `GetDate`，顺序不能反          |
| 备份寄存器写入无效               | 未取消写保护                             | 调用 `HAL_PWR_EnableBkUpAccess()` 取消写保护        |
| LCD 显示乱码                | `lcd_show_string` 的 height 小于 size | 确保 `height >= size`                          |
| 24/32 字号中文只显示部分         | 字库数据不完整                            | 用取模软件生成缺失字模，替换 `lcd-font.h` 中的占位数据           |
