# 实验 26：汉字显示

本实验在 FATFS 文件系统实验的基础上，进一步实现汉字的显示。通过 **SDIO 接口** 驱动 SD 卡，读取其中存放的 **GBK 汉字字库文件**（存放在 `SYSTEM/FONT/` 目录），提取汉字的点阵数据，最终在 **TFT-LCD** 屏幕上显示出来。同时，利用板载 **NOR Flash（W25Qxx）** 作为字库存储介质，将字库从 SD 卡复制到 NOR Flash 中，提高读取速度。通过本实验，深入理解 **GBK 汉字编码**、**点阵字库结构**、**NOR Flash 存储规划**、**字库更新机制** 以及 **FATFS 与 LCD 驱动的综合应用**

### ② 汉字显示基础概念

> **目标**：理解汉字显示的基本原理和字库结构。

#### 汉字编码

| 编码标准       | 汉字数量    | 特点                      |
| ---------- | ------- | ----------------------- |
| **GB2312** | ~7000个  | 仅支持简体中文，常用字不够用          |
| **GBK**    | ~24000个 | **完全兼容GB2312**，支持繁体，最常用 |
| **BIG5**   | ~13000个 | 繁体中文                    |

**GBK 编码格式**：每个汉字占 **2 个字节**

- 高字节（区号）：`0x81 ~ 0xFE`（共 126 个区）

- 低字节（位号）：`0x40 ~ 0x7E` 和 `0x80 ~ 0xFE`（每区 190 个汉字，跳过 `0x7F`）

> 总汉字数 = 126 × 190 = **23,940 个汉字**

#### 点阵字库

每个汉字需要存储其点阵数据，决定哪些像素点亮、哪些熄灭。

| 字号        | 点阵大小  | 每行字节数 | 总行数  | 每字字节数 | 全字库大小   |
| --------- | ----- | ----- | ---- | ----- | ------- |
| **12×12** | 12×12 | 2 字节  | 12 行 | 24 字节 | ~574KB  |
| **16×16** | 16×16 | 2 字节  | 16 行 | 32 字节 | ~766KB  |
| **24×24** | 24×24 | 3 字节  | 24 行 | 72 字节 | ~1.72MB |

**点阵数据字节数计算公式**：

```
csize = (size / 8 + ((size % 8) ? 1 : 0)) * size
```

#### 字库定位公式

```
/* GBK内码 → 字库偏移量计算（text_get_hz_mat 核心算法） */
qh = *code;                          // 高字节
ql = *(++code);                      // 低字节

// 非法字符判断
if (qh < 0x81 || ql < 0x40 || ql == 0xff || qh == 0xff) {
    // 填充全0（空白）
}

// 位码偏移
if (ql < 0x7f)     ql -= 0x40;
else               ql -= 0x41;

qh -= 0x81;                         // 区号偏移

// 偏移量 = ((区号 × 190) + 位号) × 每个汉字字节数
foffset = ((unsigned long)190 * qh + ql) * csize;
```

**示例：汉字“正”（GBK: D5 FD）**

```
qh = 0xD5, ql = 0xFD
ql > 0x7F → ql = 0xFD - 0x41 = 188
qh = 0xD5 - 0x81 = 84
foffset = ((84 × 190) + 188) × 32 = 516736
```

#### 点阵数据解析

```
16×16 点阵（csize = 32 字节）：

字节0:  行0 列0~7   (bit7~bit0)
字节1:  行0 列8~15  (bit7~bit0)
字节2:  行1 列0~7
字节3:  行1 列8~15
...
字节30: 行15 列0~7
字节31: 行15 列8~15

显示规则：
    bit = 1 → 画前景色
    bit = 0 → 画背景色（正常模式）/ 透明（叠加模式）
```

### ③ 寄存器级

> **目标**：从寄存器层面理解字库存储和 LCD 显示的配置。

#### NOR Flash（W25Qxx）关键寄存器/指令

| 指令                     | 值    | 作用              |
| ---------------------- | ---- | --------------- |
| **W25X_WriteEnable**   | 0x06 | 写使能（写入前必须执行）    |
| **W25X_ReadStatusReg** | 0x05 | 读状态寄存器（检查忙标志）   |
| **W25X_ReadData**      | 0x03 | 读数据（最多可连续读取）    |
| **W25X_PageProgram**   | 0x02 | 页编程（写入，每页256字节） |
| **W25X_SectorErase**   | 0x20 | 扇区擦除（4KB）       |

#### 字库存储规划

```
#define FONTSECSIZE         791        // 字库区域占用的扇区数（4KB/扇区）
```

### ⑤ 内存管理（自定义内存池）

> **目标**：理解本实验中的动态内存分配机制。

#### 内存使用分布

| 用途              | 内存池    | 大小     | 说明                  |
| --------------- | ------ | ------ | ------------------- |
| `fs[0]`/`fs[1]` | SRAMIN | ~数百字节  | 文件系统对象（exfuns_init） |
| `dzk` 点阵缓冲区     | SRAMIN | 最大72字节 | text_show_font 申请   |
| `fftemp` 文件对象   | SRAMIN | ~数百字节  | 字库更新时使用             |
| `tempbuf` 数据缓冲  | SRAMIN | 4KB    | 字库更新时使用             |
| `pname` 路径缓冲    | SRAMIN | 100字节  | 字库更新时使用             |
| `buf` 擦除校验缓冲    | SRAMIN | 4KB    | 字库更新时使用             |

#### 内存分配代码示例

```
// text_show_font() 中的内存分配
dzk = mymalloc(SRAMIN, csize);    // 申请 csize 字节
if (dzk == 0) return;              // 申请失败返回
text_get_hz_mat(font, dzk, size);  // 获取点阵数据
// ... 使用 dzk ...
myfree(SRAMIN, dzk);              // 释放内存
```

#### 三个内存池

| 内存池         | 位置     | 大小    | 特点                 |
| ----------- | ------ | ----- | ------------------ |
| **SRAMIN**  | 内部SRAM | 100KB | CPU和DMA都可访问（本实验使用） |
| **SRAMCCM** | CCM内存  | 60KB  | 仅CPU可访问，速度更快       |
| **SRAMEX**  | 外部SRAM | 963KB | 容量大，速度较慢           |

### ⑥ 中断/DMA 机制

> **目标**：理解本实验中的数据传输方式。

#### 本实验的方案：**无中断，无 DMA，纯 CPU 轮询 + USART 中断**

| 机制                | 是否使用 | 说明                 |
| ----------------- | ---- | ------------------ |
| **SDIO 中断**       | ❌ 否  | 字库读取通过 FATFS 轮询方式  |
| **NOR Flash DMA** | ❌ 否  | 数据量小（单字最大72字节）     |
| **LCD DMA**       | ❌ 否  | 直接 CPU 写入 LCD GRAM |
| **USART1 中断**     | ✅ 是  | 调试信息输出（可选）         |

#### 传输方式说明

- 单个汉字点阵数据最大 **72 字节**（24×24），数据量极小

- 字库更新时使用 **4KB 缓冲区**，提高写入效率

- NOR Flash 读取速度远快于 SD 卡，适合作为字库存储介质

#### USART1 中断（调试输出）

```
void USART1_IRQHandler(void)
{
    if (__HAL_UART_GET_FLAG(&g_uart1_handle, UART_FLAG_RXNE) != RESET) {
        uint8_t data = (uint8_t)(g_uart1_handle.Instance->DR & 0xFF);
        usmart_dev.scan(data);   // USMART 命令扫描（如已初始化）
    }
}
```
