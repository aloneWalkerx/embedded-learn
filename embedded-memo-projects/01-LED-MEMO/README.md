## 二、硬件事实

**来源**：正点原子《M144Z-M4最小系统板IO引脚分配表——STM32F407版.xlsx》

| 项 | 值 |
|---|---|
| LED0 | **PF9**（红色）|
| LED1 | **PF10**（绿色）|
| 所在端口 | 都是 **GPIOF** |
| 点亮方式 | **低电平点亮**（阳极经限流电阻接 VCC，阴极接 GPIO）|
| ⚠️ 是否引出 | **N —— 未引到排针**，只能用板载 LED |

**点亮逻辑推导**：

```
LED 阳极 → VCC
LED 阴极 → GPIO（PF9/PF10）
         ↓
GPIO 输出低 → 有压差 → 电流流过 → 灯亮
GPIO 输出高 → 无压差 → 灯灭
         ↓
所以：ON  = GPIO_PIN_RESET（输出低）
      OFF = GPIO_PIN_SET  （输出高）
```

## 三、代码流程

### `main()` 的执行顺序（顺序不能乱）

```c
HAL_Init();                    // ① HAL 库初始化（配 SysTick）
sys_stm32_clk_init(336,8,2,7); // ② 系统时钟 → 168MHz
delay_init(168);               // ③ 延时初始化（传 168）
led_init();                    // ④ LED 初始化
while(1) { ... }               // ⑤ 主循环
```

**为什么顺序不能乱**：
- `HAL_Init()` 必须在最前 —— 它配 SysTick，后面的延时依赖它
- `sys_stm32_clk_init()` 必须在 `delay_init()` 前 —— 延时要知道实际主频
- `led_init()` 里要开时钟，所以必须在时钟配置之后

### `led_init()` 的步骤

```c
1. LED0_GPIO_CLK_ENABLE();      // 开 GPIOF 时钟 ← 必须第一步
2. LED1_GPIO_CLK_ENABLE();      // （重复但无害）
3. GPIO_InitTypeDef ... = {0};  // 声明并清零结构体
4. 填 4 个字段：Pin / Mode / Pull / Speed
5. HAL_GPIO_Init(GPIOF, &...);  // HAL 去写寄存器
6. LED0_OFF(); LED1_OFF();      // 默认熄灭
```

## 四、⭐ 核心知识：HAL → 寄存器映射

**本项目最核心的知识点。面试问"HAL 背后动了什么"，答的就是这张表。**

### `HAL_GPIO_Init()` → 4 个寄存器

| 你填的字段 | HAL 写的寄存器 | 位域 | 源码位置 |
|---|---|---|---|
| **`.Speed`** | `GPIOF->OSPEEDR` | 每引脚 2 位 | `stm32f4xx_hal_gpio.c:194~197` |
| **`.Mode` 的输出类型部分** | `GPIOF->OTYPER` | 每引脚 1 位 | 同上 `:200~203` |
| **`.Pull`** | `GPIOF->PUPDR` | 每引脚 2 位 | 同上 `:212~215` |
| **`.Mode` 的方向部分** | `GPIOF->MODER` | 每引脚 2 位 | 同上 `:231~234` |

### ⭐ 一个精巧的设计：`.Mode` 一个字段管**两个**寄存器

HAL 用**位掩码**把 `.Mode` 拆成两半：

```c
// 写 OTYPER 时取"输出类型"那半
temp |= (((GPIO_Init->Mode & OUTPUT_TYPE) >> OUTPUT_TYPE_Pos) << position);

// 写 MODER 时取"方向"那半
temp |= ((GPIO_Init->Mode & GPIO_MODE) << (position * 2U));
```

| 宏定义 | 值 | `& GPIO_MODE`(0x03) | `& OUTPUT_TYPE`(0x10) |
|---|---|---|---|
| `GPIO_MODE_OUTPUT_PP` | `0x01` | `0x01` → MODER=输出 | `0x00` → OTYPER=**推挽** |
| `GPIO_MODE_OUTPUT_OD` | `0x11` | `0x01` → MODER=输出 | `0x10` → OTYPER=**开漏** |

**两者只差一个 bit，却影响两个寄存器。**

### ⚠️ 顺序细节：`MODER` 为什么写在最后

HAL 里寄存器写入顺序是：`OSPEEDR` → `OTYPER` → `PUPDR` → **`MODER`**（最后）

**原因**：`MODER` 决定引脚方向。放在最后 → **引脚直到最后一步才真正变成输出**。
前面配 `PUPDR`/`OTYPER`/`OSPEEDR` 时引脚还是输入态，`PUPDR` 这时是有意义的（定住电平、防毛刺）。

**这是 ST 有意为之的顺序。**

### 其他 HAL GPIO 函数

| HAL 函数 | 动的寄存器 | 源码行 |
|---|---|---|
| `HAL_GPIO_WritePin()` | **`BSRR`** | `:418`（置位）/ `:422`（复位）|
| `HAL_GPIO_TogglePin()` | `ODR`（读）+ `BSRR`（写）| `:441` / `:444` |
| `HAL_GPIO_ReadPin()` | `IDR` | `:382` |

**`WritePin` 源码**：
```c
GPIOx->BSRR = GPIO_Pin;                          // 行 418：输出高（BSRR 低16位）
GPIOx->BSRR = (uint32_t)GPIO_Pin << 16U;         // 行 422：输出低（BSRR 高16位）
```

**函数注释原文（行 396）**：
> "This function uses **GPIOx_BSRR** register to allow **atomic** read/modify"

### 时钟使能宏展开（`__HAL_RCC_GPIOF_CLK_ENABLE()`）

源码：`stm32f4xx_hal_rcc_ex.h:2079`

```c
#define __HAL_RCC_GPIOF_CLK_ENABLE()   do { \
        __IO uint32_t tmpreg = 0x00U; \
        SET_BIT(RCC->AHB1ENR, RCC_AHB1ENR_GPIOFEN);\   // 置位 AHB1ENR 第 5 位
        /* Delay after an RCC peripheral clock enabling */ \
        tmpreg = READ_BIT(RCC->AHB1ENR, RCC_AHB1ENR_GPIOFEN);\  // ← 回读插延迟
        UNUSED(tmpreg); \
    } while(0U)
```

**位定义**（`stm32f407xx.h:9906`）：
```c
#define RCC_AHB1ENR_GPIOFEN_Pos   (5U)
#define RCC_AHB1ENR_GPIOFEN       (0x1UL << 5)   // = 0x20
```

**⭐ 那个"回读"是干什么的？**
> 使能时钟后，外设寄存器不是立刻可访问的——需要几个时钟周期。
> HAL 用一次**多余的读操作**插入这个延迟。
> 为什么不用空循环？因为编译器可能优化掉空循环，**但读 volatile 变量优化不掉**。

### 寄存器速查表（GPIO）

| 寄存器 | 全称 | 作用 | 位宽 |
|---|---|---|---|
| `MODER` | Mode Register | 模式：00输入/01输出/10复用/11模拟 | 每引脚 2 位 |
| `OTYPER` | Output Type Register | 输出类型：0推挽/1开漏 | 每引脚 1 位 |
| `OSPEEDR` | Output Speed Register | 输出速度 | 每引脚 2 位 |
| `PUPDR` | Pull-Up/Pull-Down Register | 上下拉：00无/01上拉/10下拉 | 每引脚 2 位 |
| `IDR` | Input Data Register | 输入数据（只读）| 每引脚 1 位 |
| `ODR` | Output Data Register | 输出数据（**读-改-写**）| 每引脚 1 位 |
| `BSRR` | Bit Set/Reset Register | 原子置位/复位（写1有效）| 低16置位/高16复位 |
| `AFRL/AFRH` | Alternate Function | 复用功能选择 | 每引脚 4 位 |

## 五、系统时钟树

**配置**：`sys_stm32_clk_init(PLLN=336, PLLM=8, PLLP=2, PLLQ=7)`，HSE = 8MHz

```
HSE 8MHz
  │
  ├─ /PLLM(8) ──→ 1MHz  (VCO 输入，规格 1~2MHz)
  │                  │
  │                  ×PLLN(336)
  │                  ↓
  │              336MHz  (VCO 输出，规格 100~432MHz)
  │                  │
  │      ┌───────────┼───────────┐
  │      │           │           │
  │   /PLLP(2)   /PLLQ(7)        │
  │      ↓           ↓           │
  │   168MHz      48MHz          │
  │   SYSCLK    (USB/SDIO/RNG)   │
  │      │
  │   /AHB(1)
  │      ↓
  │   168MHz (HCLK = AHB)
  │      │
  │   ┌──┴──────────────┬──────────────┐
  │   │                 │              │
  │ /APB1(4)         /APB2(2)      (AHB1 直连)
  │   ↓                 ↓              ↓
  │ 42MHz             84MHz        GPIOA~GPIOH ✅
  │ USART2/3          USART1
  │ I2C1/2/3          SPI1
  │ CAN1/CAN2         TIM1/8~11
  │ TIM2~7 ← ★
  └──────────────────────
```

### ⚠️ 两个必考细节

**① 定时器时钟会倍频**
> `TIM2~7` 挂在 **APB1（42MHz）**，但 **APB1 分频 ≠ 1 时，定时器时钟 = 2 × 42 = 84MHz**。
> `TIM1/8~11` 挂在 APB2（84MHz），定时器时钟 = 2 × 84 = **168MHz**。

**② 进阶：VCO 输入建议取 2MHz**
> 现在 PLLM=8 → VCO 输入 = 1MHz（在规格内，但 ST 建议 2MHz 以降低抖动）。
> 改为 2MHz：`sys_stm32_clk_init(168, 4, 2, 7)`
> （HSE/4 = 2MHz，2 × 168 = 336MHz，336/2 = 168MHz ✅）

## 七、⭐ 面试题库（标准答案）

### A 类：GPIO 基础

---

#### 1. GPIO 有哪几种模式？

STM32F4 的 GPIO 通过 `MODER` 寄存器（每引脚 2 位）配置，共 **4 种**：

| MODER | 模式 | 说明 |
|---|---|---|
| `00` | **输入** | 再由 `PUPDR` 细分：浮空 / 上拉 / 下拉 |
| `01` | **通用输出** | 再由 `OTYPER` 细分：推挽 / 开漏 |
| `10` | **复用功能** | 引脚交给外设（USART/SPI/CAN 等），由 `AFRL/AFRH` 选 AF 号 |
| `11` | **模拟** | 关闭施密特触发器，引脚直连 ADC/DAC |

**补充**：
- **模拟模式下读 `IDR` 无意义**（数字通路已断开）
- **模拟模式下必须关闭上下拉**（`PUPDR = 00`），否则会分压影响 ADC 采样精度

---

#### 2. 推挽和开漏的区别？各用在哪？

**这是输出级（`OTYPER`）的两种结构。**

**【推挽 Push-Pull】**

- **结构**：内部有上下两个 MOS 管，上管接 VCC，下管接 GND
- **输出高**：上管导通、下管截止 → 引脚被**主动拉到 VCC**
- **输出低**：下管导通、上管截止 → 引脚被**主动拉到 GND**
- **特点**：能**主动输出高电平和低电平**，驱动能力强，边沿陡
- **用途**：普通数字输出 —— LED、片选 CS、蜂鸣器、继电器控制

**【开漏 Open-Drain】**

- **结构**：只有下管，没有上管
- **输出低**：下管导通 → 引脚被拉到 GND
- **输出高**：下管截止 → 引脚呈**高阻态**（⚠️ 不是高电平！）
- **特点**：**只能拉低，不能主动拉高**；高电平必须靠**外部上拉电阻**
- **用途**：I2C（SDA/SCL）、多设备共享的信号线、需要电平转换的场合

**【为什么 I2C 必须用开漏】**（面试深挖会问）

1. **实现"线与"**：I2C 是多设备共享总线，语义是"只要有任一设备拉低，总线就是低"。
   开漏天然支持这个语义——所有设备的高阻态相当于"不干涉"，任一设备拉低即生效。
2. **避免短路**：如果用推挽，一个设备输出高（上管导通）、另一个输出低（下管导通），
   两个管子直接对通 → **大电流 → 可能烧芯片**。
3. **支持时钟同步和多主仲裁**：这两个机制都依赖"线与"。
4. **电平转换**：上拉电阻可以接到 3.3V 或 5V，实现不同电压域互连。

**【一句话记忆】**

```
推挽 = 能推能拉（主动输出高/低）
开漏 = 只能拉低，高电平靠上拉
```

---

#### 3. 为什么配置外设前第一步必须使能 RCC 时钟？不开会怎样？

**【答案】**

STM32 采用**门控时钟（Clock Gating）**设计：每个外设都有独立的时钟开关（在 `RCC` 寄存器里），**默认关闭**，目的是省电（不用外设就不耗电）。

**时钟不开时会发生什么**：

- 外设的逻辑电路**没有时钟驱动 → 完全不工作**
- 对该外设寄存器的**写入会被忽略**
- 对该外设寄存器的**读取返回复位默认值**（通常是 0）

**【最坑的地方：它不报错】**

这是这道题的**真正得分点**：

- 编译**通过**
- 下载**成功**
- 代码逻辑**看起来完全正确**
- 外设**就是没反应，而且没有任何错误提示**

**原因**：从 CPU 的角度看，写寄存器是"成功"的——总线有响应、没有异常。
只是外设内部没有时钟去**执行**这个配置。**这是一个静默失败（silent failure）。**

**【具体到 GPIO】**

不开 GPIOF 时钟 → 配 `MODER`/`OTYPER`/`OSPEEDR`/`PUPDR` 全部无效
→ 引脚保持复位状态（浮空输入）→ **LED 不亮，而且不知道为什么**

**【工程习惯】**

> 写任何外设初始化的**第一行，永远是开时钟**。
> 排查"外设不工作"这类问题时，**第一步就是确认时钟开了没有**。

---

#### 4. `BSRR` 和 `ODR` 的区别？为什么 HAL 用 `BSRR`？

**【本质区别：原子 vs 非原子】**

**`ODR`（Output Data Register）**

- 32 位寄存器（低 16 位有效），**每一位对应一个引脚的电平**
- 要改某一位，必须是"**读-改-写**"三步：
  ```
  ① 读出整个 ODR
  ② 用位运算改目标位
  ③ 整个写回 ODR
  ```
- 对应 C 代码：`GPIOF->ODR |= (1 << 9);`
- ⚠️ **非原子**：如果 ① 和 ③ 之间来了**中断或任务切换**，
  中断里改了别的引脚，③ 写回时会用**旧值覆盖**，把中断的修改抹掉

**`BSRR`（Bit Set/Reset Register）**

- **低 16 位 = 置位位**（写 1 → 对应引脚输出高）
- **高 16 位 = 复位位**（写 1 → 对应引脚输出低）
- **写 0 的位没有任何影响**
- 一次写完成，**不需要读回 → 天然原子**

**【为什么 HAL 用 BSRR】**

`HAL_GPIO_WritePin` 的源码注释（`stm32f4xx_hal_gpio.c:396`）：

> "This function uses **GPIOx_BSRR** register to allow **atomic** read/modify"

**ST 官方明确说了是为了"原子"。**

**【代码对比】**

```c
// ❌ 非原子（用 ODR）
GPIOF->ODR |= (1 << 9);          // 编译成：读 → 改 → 写回

// ✅ 原子（用 BSRR）
GPIOF->BSRR = (1 << 9);          // 输出高：低 16 位写 1
GPIOF->BSRR = (1 << (9 + 16));   // 输出低：高 16 位写 1
```

**【为什么要原子 —— 具体场景】**

在**中断**或**多任务（RTOS）**环境下，读-改-写中间被打断会破坏其它引脚的位。
`BSRR` 一次写完成，**不可能被打断**。

**【延伸】**

> 同样的道理在 FreeRTOS 里叫**临界区**——保护"读-改-写"这类非原子操作。
> 理解了 `BSRR` 的原子性，就理解了为什么 RTOS 需要临界区和互斥锁。

#### 5. 其他 GPIO 高频题

**Q：`BSRR` 的高 16 位是什么？**
> **复位位**。写 1 → 对应引脚输出低（清零 `ODR` 的对应位）。
> 低 16 位是置位位（写 1 → 输出高）。

**Q：上拉/下拉电阻一般多大？选大了会怎样？**
> STM32 内部约 **30~50 kΩ**；外部常用 **4.7k~10k**。
> **选太大** → 上升沿变慢（RC 时间常数大），高速通信来不及拉高；
> **选太小** → 功耗大，可能超出 IO 灌电流上限。

**Q：上下拉在什么模式下有意义？**

| 模式 | 上下拉 | 为什么 |
|---|---|---|
| 输入（浮空）| ✅ **必须有** | 无外部驱动时读数随机跳，上下拉给确定默认值 |
| 输入（上拉/下拉）| ✅ | 本身就是这个用途 |
| 开漏输出 | ✅ **必须有上拉** | 开漏只能拉低，高电平靠上拉 |
| **推挽输出** | ❌ **无意义 → `NOPULL`** | 驱动器主动输出，上下拉不影响稳态电平 |
| 复用推挽 | ❌ 无意义 | 同上 |
| 模拟（ADC）| ❌ **必须关闭** | 上下拉会分压，影响采样精度 |

**Q：为什么很多板子 LED 是低电平点亮？**
> MCU 的**灌电流（sink）能力通常比拉电流（source）强**。
> STM32F407 单个 IO 约 25mA，还有总和上限 —— **必须查手册，不能想当然**。

**Q：`OSPEEDR` 速度档位怎么选？**
> LOW / MEDIUM / HIGH / VERY_HIGH。
> 速度越高 → 边沿越陡、**EMI 越大**、功耗略增。
> **够用就别调高**（本项目取 LOW，见第八章 8.6）。

### B 类：时钟

**Q：你的系统时钟是多少？怎么配的？**
> 168MHz。HSE 8MHz → /PLLM(8) → 1MHz → ×PLLN(336) → 336MHz → /PLLP(2) → **168MHz**。
> 分频：AHB = 168M，APB1 = 42M，APB2 = 84M。

**Q：APB1 挂哪些外设？APB2 呢？**
> APB1（42MHz）：USART2/3、I2C1/2/3、CAN1/CAN2、TIM2~7
> APB2（84MHz）：USART1、SPI1、TIM1/8~11、ADC

**Q：定时器时钟是多少？为什么不是 42MHz？**
> **84MHz**。因为 **APB1 分频 ≠ 1 时，定时器时钟 = 2 × PCLK1**。
> TIM1/8~11 挂在 APB2，时钟 = **168MHz**。
> ⚠️ 这是经典陷阱题。

**Q：为什么时钟使能宏里有个"回读"？**
> 插入延迟（等外设寄存器可访问）。用读 volatile 变量实现，编译器优化不掉。

---

### C 类：库函数 vs 寄存器

**Q：你用库函数还是寄存器？**

> 我用 **HAL 库**——开发效率高、ST 官方主推、跨 F4/F7/H7 系列移植方便。
>
> **但底层我清楚**：比如 `HAL_GPIO_Init()` 内部配的就是 **`MODER`/`OTYPER`/`OSPEEDR`/`PUPDR`** 这四个寄存器；
> `__HAL_RCC_GPIOF_CLK_ENABLE()` 最终是写 **`RCC->AHB1ENR`** 的第 5 位。
>
> HAL 的缺点是**封装厚、执行效率比寄存器低**，有些地方代码臃肿。
> 所以**调底层问题时我会回头看寄存器**。

**Q：`HAL_GPIO_Init()` 内部做了什么？**
> 见第四章的映射表（4 个寄存器 + 顺序为什么是 MODER 最后）。

**Q：`do{}while(0)` 包宏是为什么？**
> 保证宏在 `if/else` 里当**单条语句**使用时不会出错（不会多出分号导致断句错误）。
> 这是 C 语言宏的标准写法。

**Q：`GPIO_InitTypeDef gpio_init_struct = {0}` 里的 `{0}` 有什么用？**
> **清零**。不清零的话，未赋值的成员是**栈上的随机值**。
> 比如 `Alternate` 字段如果是乱值，复用模式会配错 AF 号。

### D 类：综合实战

**Q：编译通过但灯不亮，你怎么排查？**

> **分层排查，从软到硬**：
>
> 1. **时钟开了吗？** ← 最常见，而且**不报错**（见第八章 8.1）
> 2. **引脚号/端口对不对？** 查原理图/引脚分配表，别靠猜
> 3. **`MODER` 配成输出了吗？** （还是复位默认的输入态）
> 4. **输出电平对不对？** LED 是高电平点亮还是低电平点亮（见第八章 8.3）
> 5. **用万用表量引脚电压** —— 确认 MCU 到底输出了什么
> 6. **换件法**：换一个 LED/换一根杜邦线，确认是代码还是硬件

**Q：你的代码怎么分层的？为什么这么分？**
> app（`main.c`）/ BSP（`led.c`）/ SYSTEM / HAL 四层。
> 好处：换硬件只改 BSP，app 层不动——**面向接口编程，解耦**。
> 这和 Java 里的"接口 + 实现"是一个思路。

**Q：`#include "./BSP/LED/led.h"` 为什么用相对路径？**
> 这是正点原子教程风格。现代做法是在 Keil 里配好 **Include Paths**，直接 `#include "led.h"`，工程更干净。

## 八、⭐ 本实验常见错误与规避

> 本章只列 **GPIO 推挽输出驱动 LED** 这条链路上会实际遇到、且可复现验证的错误。
> 每条给出「现象 → 根因 → 规避 → 关联到本项目的哪一行」。

### 8.1 未使能 GPIOF 时钟就配置引脚

| | |
|---|---|
| **现象** | 引脚保持复位状态（浮空输入），LED 不亮；**编译、下载全部正常，没有任何报错** |
| **根因** | STM32 是门控时钟设计，时钟未开时对该外设寄存器的**写入被忽略**、**读取返回复位值** |
| **规避** | `LED0_GPIO_CLK_ENABLE()` 作为 `led_init()` 的第一条语句 |
| **排查** | 调试器里读回 `GPIOF->MODER`，若仍为 `0x00000000` 说明写入没生效；再查 `RCC->AHB1ENR` 的 bit5 |
| **关联** | `led.c` — `led_init()` 首行 |

### 8.2 `GPIO_InitTypeDef` 没有初始化为 0

| | |
|---|---|
| **现象** | 引脚行为与预期不符：速度档位、上下拉、复用号出现莫名其妙的取值 |
| **根因** | 结构体是**局部变量，位于栈上**，未显式赋值的成员是随机值；HAL 会把这些随机值一并写进 `PUPDR`/`OSPEEDR`/`AFR` |
| **规避** | 声明时就清零：`GPIO_InitTypeDef gpio_init_struct = {0};` |
| **关联** | `led.c` — 结构体声明行 |

### 8.3 LED 极性写反

| | |
|---|---|
| **现象** | 上电即常亮；或调用 `LED0_ON()` 反而熄灭 |
| **根因** | 板载 LED 的**阳极经限流电阻接 VCC、阴极接 GPIO**，属于**低电平点亮**：`GPIO_PIN_RESET` 才是点亮 |
| **规避** | 把极性**收敛在宏定义内部**（`LED0_ON()` 宏里做取反），业务层只写 `ON/OFF`，不关心电平 |
| **关联** | `led.h` — `LED0_ON/OFF`、`LED1_ON/OFF` 宏 |

### 8.4 输出模式却配了上下拉

| | |
|---|---|
| **现象** | 功能上通常看不出来，但配置语义是错的；在驱动能力较弱的负载上可能表现为边沿变缓、静态电流略增 |
| **根因** | `PUPDR` 管的是"**没有驱动时**把引脚拉到哪个电平"。推挽输出由内部驱动器主动拉高/拉低，稳态电平由驱动器决定，上下拉不参与 |
| **规避** | 推挽输出用 `GPIO_NOPULL`。上下拉只在三种场合有意义：**输入**（给确定默认电平）、**开漏输出**（高电平靠上拉）、**模拟输入必须关闭** |
| **延伸** | HAL 把 `PUPDR` 写在 `MODER` **之前**（`hal_gpio.c:212` vs `:231`），使引脚在配上下拉时仍处于输入态——这个顺序是有意的 |
| **关联** | `led.c` — `.Pull = GPIO_NOPULL` |

### 8.5 用 `ODR` 改引脚 —— 读-改-写不是原子操作

| | |
|---|---|
| **现象** | 在中断或 RTOS 任务并发操作同一端口时，偶发某个引脚状态被"改回"，难以复现 |
| **根因** | `ODR` 按位修改需要"读整个寄存器 → 改位 → 写回"，中间被中断插入会丢掉其它位的修改 |
| **规避** | 用 `BSRR` 直接写；或用临界区/关中断保护 |
| **关联** | 本项目的 `HAL_GPIO_WritePin` 内部就是 `GPIOx->BSRR`（`hal_gpio.c:418/422`），是安全的；但 `HAL_GPIO_TogglePin` 是"**读 `ODR` → 写 `BSRR`**"两步（`:441` / `:444`），在并发场景下不是原子的 |

### 8.6 `OSPEEDR` 速度档位选得过高

| | |
|---|---|
| **现象** | 功能正常，但示波器上可见边沿过冲/振铃；信号引出板外时还会恶化辐射发射 |
| **根因** | 速度档位越高，输出级驱动能力越强、边沿越陡，高频谐波越丰富 |
| **规避** | 按**信号速率**选档，而不是一律用最高档。LED 属于慢速信号，本项目取 `GPIO_SPEED_FREQ_LOW` 是合适的；只有 SPI/SDIO 这类高速总线才需要 HIGH |
| **关联** | `led.c` — `.Speed = GPIO_SPEED_FREQ_LOW` |

### 8.7 上电/复位窗口内引脚状态不确定

| | |
|---|---|
| **现象** | 上电瞬间 LED 闪一下 |
| **根因** | 复位期间 GPIO 默认为**浮空输入**，内部上下拉默认关闭，引脚电平由外部电路决定；从复位结束到 `led_init()` 执行完之间，存在一个不受控的窗口 |
| **规避** | ① 初始化末尾显式置为确定的熄灭态（本项目 `led_init()` 最后两行就是 `LED0_OFF(); LED1_OFF();`）<br>② 对安全相关的负载（继电器/电机），在驱动电路上加确定电平的偏置电阻 |
| **关联** | `led.c` — `led_init()` 末尾两行 |

### 8.8 `delay_init()` 的参数与实际主频不一致

| | |
|---|---|
| **现象** | 闪烁周期不是 500ms（明显偏快或偏慢） |
| **根因** | 延时基于 SysTick 计数，计数换算依赖主频。`sys_stm32_clk_init()` 改了主频，而 `delay_init()` 仍传旧值 → 延时按错误比例换算 |
| **规避** | `sys_stm32_clk_init(336,8,2,7)` 得到 168MHz，`delay_init(168)` 必须与之对应；更稳妥的写法是直接传 `SystemCoreClock` |
| **关联** | `main.c` — 前三行的顺序与参数 |

### 8.9 直接用 GPIO 驱动负载时的电流限制

| | |
|---|---|
| **现象** | LED 偏暗或发烫，长时间运行后 IO 损坏 |
| **根因** | IO 有**单脚电流上限**与**整片总电流上限**（须查数据手册），且输出高/低时的驱动能力**并不对称**（通常灌电流能力强于拉电流） |
| **规避** | 串限流电阻并按工作点计算阻值；多个 LED 同时点亮时核算电流总和；大电流负载用三极管/MOS 驱动，不直接接 IO |
| **关联** | 本实验用的是板载 LED（已内置限流电阻）；**外接 LED 时必须自己算** |
